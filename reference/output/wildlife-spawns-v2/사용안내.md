# 야생 랜덤스폰 · 계절 연동 v3

대형 구조물은 기존에 분리했던 585개 중에 있었습니다. 파일명 natural_* 때문에 이전 보고서에서 일반 자연물로 잘못 분류한 것을 수정했습니다.

## 구성
- 16.schem: 덩굴 고대문 12개 / 17.schem: 이끼 낀 유적 32개
- 19.schem: 거목 수호상 4개 / 20.schem: 버섯 수호상 54개
- 21.schem: 거대 거목·버섯 수호상 60개
- 대형 구조물 162개 + 일반 자연물 423개 = 585개. 템플릿/블록 상태를 모두 대조했고 생성 풀에서 중복·누락 없이 한 번씩 참조합니다. v2 대비 NBT 파일 585개는 바이트까지 동일합니다.
- 몹 138종 중 128종은 일반 자연스폰, 10종만 해당 구조물 주변 조건. 28종은 무리 설정. 기존 별·포획 확률·전투 수치는 유지합니다.

## 적용
기존 custom-creatures-v3 서버·클라이언트·모델 리소스가 먼저 필요합니다. 이번 묶음은 스폰 플러그인과 설정, 통합 월드 생성 데이터팩을 제공합니다.
1. 야생 서버를 종료하고 server/plugins 파일들을 기존 plugins에 병합합니다. 기존 chacademia-wildlife-0.1.0/0.2.0.jar는 제거하고 0.3.0 하나만 사용합니다. 학교·던전 서버에는 야생 스폰 설정을 설치하지 않습니다.
2. worlds 기본값은 world. ChAcademiaWildlife/config.yml worlds와 MythicMobs/randomspawns/chacademia_wildlife.yml Worlds를 실제 야생 월드 이름으로 함께 수정합니다.
3. MythicMobs-설정-병합.yml의 항목만 기존 config-spawning.yml에 병합합니다. GenerateSpawnPoints가 true여야 ADD 방식이 동작합니다.
4. datapacks/Chacademia-Terralith-1.21.4-v3.zip을 야생 월드/datapacks에 넣습니다. 기존 차카데미 Terralith v1/v2 ZIP을 함께 활성화하지 말고 v3 하나로 교체합니다. Terralith 2.5.8을 포함한 통합본이므로 동일 Terralith 팩도 중복 활성화하지 않습니다. 기존 월드를 삭제할 필요는 없습니다.
5. 재시작. 구조물 생성 설정은 새 청크부터 적용됩니다. 이미 생성된 옛 구조물은 과거 woodland_*/enchanted_* ID로 남아 있으며 새 희귀 몹 조건에 자동 재분류되지 않습니다. WorldEdit로 붙인 구조물도 자연 생성 기록으로 인식하지 않습니다.
6. 보호 지역은 config.yml excluded-areas에 중심과 반경을 지정합니다. 기본 world 0,0 반경96. WorldGuard 영역 자동 연동은 아닙니다.

## 관리 명령
- /야생관리 check <몹ID>: 서 있는 위치에서 실패하는 서식지·지형 조건 확인. 플레이어 거리와 개체 제한은 이 진단에서 생략합니다.
- /야생관리 structures: 주변에 로드된 차카데미 구조물 기록 확인.
- /야생관리 reload: 서식지/플러그인 설정 재적용. 미씩몹 스폰 파일 변경 후에는 /mm reload도 실행합니다.
- /locate structure chacademia:ruined_gate 등: 운영자용 구조물 위치 찾기. 새 지형을 탐색하므로 관리 시에만 사용합니다. 스폰 처리에서는 locate를 호출하지 않습니다.

## 구조물 생성 조건
전용 다섯 종류는 하나의 landmarks 구조물 세트에서 경쟁합니다. 셀 간격24청크, 최소 분리12청크, 후보 빈도0.65. 거대 수호상 가중치1, 나머지 각2. natural_large 세트 후보와6청크 이내 겹치는 후보는 제외합니다. 바이옴 조건도 맞아야 하므로 384블록마다 반드시 생긴다는 뜻은 아닙니다.
기본 자연물은 기존 small/medium/large 세트의 간격과 빈도를 유지합니다. 대형 구조물 162개를 그 풀에서 제거해 나무로 취급하지 않게 했습니다. 개별 구조물 ID와 생성 바이옴은 대형구조물-목록.html에 있습니다.

## 몹 조건
- MythicMobs RandomSpawns ADD가 최초 생성 지점과 시점을 담당합니다. ChAcademiaWildlife의 cahabitat 조건은 바이옴/시간/지면/공간/거리/구조물/개체 수를 검사하고 무리 개체를 추가합니다. 별도 주기적 최초 스폰 엔진은 없습니다.
- 후보 지점 시도확률: 일반4.5%, 2성1.8%, 3성0.4%, 빙하핵 보스0.06%. 전역 규칙 재시도 간격20/60/240/1800초. 같은 조건의 여러 몹이 경쟁하므로 시간당 출현율과 다릅니다.
- 이로치 일반4095 : 이로치1. 추가 무리 개체는 각각1/4096. 이름 앞에 이로치를 붙이지 않으며 기존 노란 이름 표시를 유지합니다. config.yml shiny-denominator와 RandomSpawns Types를 함께 조절합니다.
- 생존/모험 플레이어24~80블록. 로드된 청크만 검사합니다. 지역 커스텀 야생 몹24개 상한(수평96/수직64 반경 상자). 동종 상한은 개별 표에 표시. 펫 제외.
- 수중형은 몸체 전체 물, 물가 조건은 수평5블록/수직-2~+1의 물. 큰 몹은 넓은 몸체·발판 검사. 비행형도 안전한 LAND 후보에서 시작합니다.
- 지상형은 햇빛값1 이상, 동굴형은 블록 조명7 이하. 밤13000~23000, 낮0~12000. 보름달/뇌우는 개별 표 조건.
- 구조물 거리는 실제 구조물 조각 경계부터 수평48~72블록. 높이는 구조물 최하단-12~최상단+24. 일반 나무·자연물은 희귀종의 구조물 조건을 만족하지 않습니다. 구조물 캐시는 청크 로드/언로드에 맞춰 갱신합니다. 스폰 판정에서 청크 탐색이나 강제 생성은 하지 않습니다.
- 자연 생성 표시된 몹만 생성60초 후 플레이어128블록 밖이면10초 주기로 정리합니다. 명령 소환/펫은 제외합니다.

## 계절 조건
기존 MagicCodexBridge의 ClimateService를 읽습니다. 별도 달력이나 클라이언트 값을 사용하지 않습니다. MagicCodexBridge 0.26.0으로 실제 연동을 검증했습니다. 해당 월드를 MagicCodexBridge/climate.yml worlds에도 등록해야 합니다.
26종만 출현 계절을 지정하고 나머지112종은 연중입니다. 봄6종 / 봄·여름5종 / 여름4종 / 가을5종 / 겨울6종. 개별 이름은 계절별-출현몹.md와 HTML 조건표에 있습니다.
habitats.yml의 각 몹 seasons 필드로 변경합니다. 예: seasons: [spring, summer] 또는 seasons: [봄, 여름]. 빈 목록 seasons: [] 또는 필드 생략은 연중. 저장 후 /야생관리 reload. 다른 필수 서식지 필드는 유지하세요. 지원하지 않는 계절 값이나 목록 아닌 값은 재적용을 거부하고 이전 유효 설정을 유지합니다.
계절은 새로운 스폰 후보와 추가 무리 개체에 적용합니다. 이미 출현한 몹이나 보유 펫의 상태는 그대로 이어집니다. 같은 계절의 일반·이로치에는 동일한 조건이 적용됩니다.
계절 서비스가 없거나 그 월드의 계절이 비활성화되어 있으면 계절 지정 몹은 생성되지 않습니다. 연중 몹은 계절 서비스 없이도 기존 조건으로 생성됩니다. /야생관리 check <몹ID>는 출현 계절 아님 / 계절 정보 없음으로 구별합니다.
운영자 명령 /codexclimate season 봄|여름|가을|겨울은 바로 조건에 반영됩니다. /codexclimate auto on|off로 자동 전환을 관리합니다. 계절 서비스 자체의 날짜 설정은 기존 climate.yml에서 관리합니다.

## 검증 범위
검증결과.txt와 structure-audit.json, natural-generation-check.json을 확인하세요. 격리 서버에서 실제 생성 시작점과 스폰 조건을 검사합니다. 전체585종 템플릿 등록은 전부 대조하지만, 585종 외형을 지형마다 직접 플레이 검수한 것은 아닙니다. 운영 서버의 동접 부하·분포 체감은 추후 플레이 테스트가 필요합니다.
