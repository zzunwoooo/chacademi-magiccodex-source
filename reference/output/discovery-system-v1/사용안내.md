# 마법 발견 시스템 0.1.0

구성: **MagicDiscovery 0.1.0**, **MagicCodexBridge 0.8.0**, **Fabric 모드 0.16.0 / Minecraft 1.21.4**.

## 설치와 테스트

1. 서버를 종료하고 `magic-discovery-0.1.0.jar`를 `plugins`에 추가합니다.
2. 기존 MagicCodexBridge JAR는 `magic-codex-bridge-0.8.0.jar`로 교체합니다. 이전 버전과 동시에 두지 않습니다. 기존 Bridge 설정은 유지합니다.
3. 서버를 다시 시작하면 `plugins/MagicDiscovery`에 설정 파일과 SQLite 데이터베이스가 생성됩니다.
4. 모드는 0.16.0을 사용합니다. `/discoverypreview` 또는 `/discoverypreview harvest_wind`로 알림·효과음만 확인할 수 있습니다. 이 명령은 권한·실제 획득·칭호를 지급하지 않습니다.

서버 플러그인은 직접 설치하는 방식입니다. 운영 서버 폴더에 자동 설치하지 않았습니다.

## 이번에 구현한 범위

사용자가 작성 완료한 62개 마법의 조건 원문을 유지했습니다. 마법 이름·아이콘·권한은 최종 200종 목록과 맞췄습니다. 기존 모드 마법 YAML의 효과·설명·획득 조건은 수정하지 않습니다.

- **27종**은 일반 게임 행동으로 자동 판정합니다. 줍기, 농작물 3종 각각의 횟수, 점프/달리기, 낙하 후 사망, 양털 깎기, 묘목 심기, 닭 먹이, 원거리 화살, 화로 음식, 촛불, 폭죽, 낚싯대, 불타는 몬스터, 착용 갑옷 파손, 물로 흑요석 생성 등을 포함합니다.
- **메테오 스트라이크**는 본인을 제외한 다른 화염 마법 31종의 권한 보유를 확인합니다. 일부 마법이 이 62종 밖에 있더라도 최종 목록 기준을 사용합니다.
- **되돌이 칼날**의 윈드커터 50회 사용은 Bridge 0.8.0의 성공한 마법 사용과 자동 연결됩니다.
- 수업·책·친구·기숙사·서클·계절·기온·펫·대장간·전용 실습, 마법별 처치/조리/패시브 마나 소비는 아직 원본 시스템이 없으므로 **서버 명령어와 DiscoveryService API 연결을 준비했습니다. 연결 전에는 해당 조건이 저절로 달성되지 않습니다.**

`62개-조건-연동표.md`에서 모든 마법의 입력 이름과 목표치를 볼 수 있습니다. 표의 `서버 연동 필요`에는 Bridge와 이미 연결된 `cast.vacuum_cleave`도 포함되어 있으므로 위 설명을 함께 참고합니다.

## 조건 판정의 세부 기준

- Survival/Adventure에서만 행동을 기록합니다. Creative/Spectator에서는 획득하지 않습니다.
- 이미 해당 권한이 있으면 재획득이나 최초 칭호를 추가 지급하지 않습니다. OP 또는 와일드카드로 이미 마법 권한을 가진 테스트 계정도 이 규칙을 따릅니다.
- 아이템 줍기는 스택 수가 아니라 실제 주운 개수를 셉니다. 가득 찬 인벤토리 조건은 공간 부족으로 아이템을 주우려는 시도로 판정합니다.
- 어린 밀·당근·감자는 각각 12개가 필요하며 완전히 자란 작물은 제외합니다. 닭 먹이와 촛불은 양손을 지원합니다.
- 회전은 방향을 바꾸며 흔드는 동작을 누적하지 않습니다. 제자리 10바퀴는 이동·순간이동 시 초기화합니다. 고온 상승기류는 서버가 알려준 30도 이상 상태에서 성공한 상승 기류 사용 후 공중에서 한 바퀴 회전해야 합니다.
- 불붙은 상태 30초는 연속 600틱입니다. 소화·죽음·재접속 시 이 연속 시간은 초기화합니다. 화염 도트 피해는 하트 수가 아닌 Minecraft 피해 수치로 셉니다.
- 흑요석은 최근 10초 안에 플레이어가 직접 놓은 물과 그 흐름을 추적해 생성 원인을 확인합니다. 기존 자연 물, 디스펜서 물, 소유자를 알 수 없는 물에는 임의로 근처 플레이어의 공적을 부여하지 않습니다.
- 낮은 확률로 습득하는 수업 마법은 기본 **10%**입니다. `discoveries.yml`의 각 `chance`를 조절하세요. 확률 판정은 수업 완료 이벤트마다 한 번이며, 로그인/주기 검사로 재추첨하지 않습니다.
- `condition-text`는 설명 원문입니다. 실제 판정은 `requirements`, `prerequisites`, `chance`가 결정합니다. 조건 변경 후에는 서버를 재시작하세요.

## 아직 없는 시스템 연결

다음 명령은 콘솔 또는 `magicdiscovery.admin` 권한자 전용입니다. 일반 클라이언트에서 달성했다고 주장하는 패킷으로 획득할 수 없습니다.

```text
magicdiscovery signal 닉네임 lesson.wind.basic
magicdiscovery signal 닉네임 book.flight
magicdiscovery signal 닉네임 friend.added
magicdiscovery signal 닉네임 dormitory.assigned
magicdiscovery state 닉네임 state.circle 6
magicdiscovery state 닉네임 state.temperature 32
magicdiscovery state 닉네임 state.flight_prohibited 1
magicdiscovery signal 닉네임 cook.hearth_touch 4
magicdiscovery signal 닉네임 kill.wind.one_hit
magicdiscovery signal 닉네임 kill.fire
magicdiscovery signal 닉네임 mana.trajectory_acceleration 50
magicdiscovery signal 닉네임 academy.all_spots
magicdiscovery signal 닉네임 anomaly.spring
```

`signal`은 실제로 확인된 횟수/소비량을 더합니다. 같은 행동을 여러 번 호출하면 여러 번 기록되므로, 외부 시스템에서 실제 이벤트당 한 번 호출하세요. `state`는 현재 상태로 덮어씁니다. 서클 값은 저장되며, 기온과 비행 금지 구역 상태는 재접속할 때 다시 전달해야 합니다. 구역을 벗어나면 비행 금지 값을 0으로 갱신하세요.

자바 플러그인에서는 서버 메인 스레드에서 사용할 수 있습니다.

```java
DiscoveryService discoveries = Bukkit.getServicesManager().load(DiscoveryService.class);
boolean accepted = discoveries.signal(player.getUniqueId(), "book.flight", 1);
discoveries.state(player.getUniqueId(), "state.circle", 6);
// Bridge를 통하지 않은 별도 시전 시스템일 때만 사용. Bridge와 이중 호출하지 마세요.
discoveries.cast(player.getUniqueId(), "vacuum_cleave", 30);
```

`false`는 알 수 없는 이벤트, 잘못된 수치, 플레이어 로딩 미완료 등을 뜻합니다. 플러그인 의존성에는 `depend: [MagicDiscovery]` 또는 `softdepend`를 선언하세요. 플레이어 데이터는 비동기로 읽기 때문에 접속 이벤트 직후에는 아직 준비되지 않았을 수 있습니다.

권한은 획득 DB에 영구 기록하고 접속 시 Bukkit 권한으로 복원합니다. LuckPerms가 있으면 LuckPerms에도 영구 노드를 저장합니다. 없어도 기존 Bridge의 `Player.hasPermission` 조회와 연동됩니다.

## 최초 획득 칭호

기본 `config.yml`의 `title-scope: server-first`는 **서버 전체에서 해당 마법을 최초로 획득한 한 명**입니다. `player-first`로 설정하면 각 플레이어에게 마법당 한 번 수령 자격이 생깁니다. 이 설정은 이후의 새 획득부터 적용되므로 운영 시작 전에 결정하세요.

칭호 아이템은 지금 생성하지 않았습니다. 나중에 실제 칭호 아이템을 손에 들고 다음 명령을 실행하면 됩니다.

```text
/magicdiscovery title harvest_wind
```

아이템 이름·로어·커스텀 데이터가 포함된 복사본 한 개를 보상으로 등록합니다. 실제로 칭호를 적용하는 동작은 그 아이템의 원본 칭호 시스템이 담당합니다. 설정은 `titles.yml`에 저장됩니다.

보상이 준비되면 획득 시 또는 접속 시 지급을 시도합니다. 인벤토리가 가득 찼거나 아이템을 아직 등록하지 않았으면 권리가 보관됩니다. `/칭호수령`으로 나중에 받을 수 있습니다. 일반 아이템처럼 바닥에 떨어뜨려 유실시키지 않습니다.

지급 전 DB 예약을 해 중복 지급을 막습니다. **지급 도중 서버가 강제 종료되어 결과가 불명확한 경우는 자동 재지급하지 않습니다.** 인벤토리 안의 지급 식별자가 있으면 복구 처리하고, 없으면 관리자가 로그/아이템 보유 여부를 확인해야 합니다. 외부 아이템 지급과 DB를 하나의 원자적 작업으로 만들 수 없으므로, 이 경우는 누락 여부를 확인해 수동 복구하는 방식입니다.

## 저장과 부하

서버 스레드에서 반복 파일 저장을 하지 않습니다. 누적치는 변경된 플레이어만 기본 5초 간격으로 별도 스레드의 SQLite 트랜잭션에 저장하고, 접속 종료/플러그인 종료 때도 저장합니다. 획득과 서버 최초 기록은 같은 트랜잭션으로 즉시 확정합니다. 강제 종료 시 아직 저장하지 않은 일반 누적 행동은 최대 저장 주기만큼 손실될 수 있습니다.

모든 조건을 매 틱 검사하지 않고 해당 행동에 연결된 조건만 검사합니다. 연속 화상 여부는 가벼운 상태 확인으로 추적하고, 몬스터 검색은 아직 해당 마법을 배우지 않은 플레이어만 기본 2초 간격으로 분산합니다. 이미 완성된 조건과 같은 수치는 반복 저장하지 않습니다.

DB는 `discoveries.db`와 SQLite의 `-wal`, `-shm` 파일을 사용합니다. 백업은 서버 종료 후 폴더 전체를 복사하는 것이 간단합니다. 여러 서버가 각각 다른 DB를 사용하면 최초 발견 기록도 서버별로 나뉩니다.

## UI와 효과음

상단 중앙 알림은 약 4.5초 표시하고 페이드 인/아웃합니다. 아이콘과 글자는 모드가 동적으로 렌더링합니다. 공통 PNG 한 장과 직접 합성한 약 2.15초/19KB OGG 한 개를 재사용합니다.

숨겨진 HUD나 열린 인벤토리에서는 알림을 기다렸다가 표시합니다. 화면에 표시 완료된 알림만 서버에 확인을 보내며 재전송은 중복 표시하지 않습니다. 칭호 보상과 도감 권한은 서버가 처리하므로 UI를 못 본다고 획득이 취소되지 않습니다.

## 검증 범위

모드/두 플러그인의 빌드와 단위 테스트, 62개 설정 로딩, 복합 조건, DB 재시작, 동시 최초 발견, 중복 획득과 보상 예약, 수신 데이터 검증을 확인했습니다. Minecraft 테스트 월드에서 실제 통신 형식으로 알림·아이콘·텍스트·OGG·중복 처리·GUI 대기를 확인하고, 별도 Gale 1.21.4(Paper 계열) 서버에서 두 플러그인의 로딩/설정/DB/명령어/종료를 검사했습니다.

**운영 서버에서 모든 62개 행동을 실제로 수행한 검증은 아닙니다.** 아직 없는 외부 시스템을 연결한 뒤 해당 동작과 월드 보호 플러그인, 커스텀 몬스터·스킬 조합은 실제 서버에서 확인해야 합니다.
