# 의뢰 게시판 · 관리자 편집창

클라이언트 0.32.0 / 서버 MagicCodexBridge 0.24.0 / Minecraft 1.21.4

## 사용하는 방법

- `/의뢰`: 학생용 게시판.
- `/의뢰관리`: 관리자 편집창. OP 또는 `magiccodex.quests.admin` 권한이 필요합니다.
- 왼쪽 목록에서 의뢰 선택 → 내용 변경 → **저장 · 반영**.
- **+ 새 의뢰** → 고유 ID, 제목, 설명, 조건, 보상을 입력 → 저장.
- ID는 처음 저장한 뒤 고정됩니다. 설명은 여러 줄 입력할 수 있습니다.
- 기본 정보 / 클리어 조건 / 보상 / 공개 설정 탭으로 구분합니다.
- 내용이 화면보다 길면 오른쪽 ↑↓ 버튼 또는 입력칸 바깥에서 마우스 휠로 이동합니다. 여러 줄 입력칸 위에서는 해당 입력칸 내용이 스크롤됩니다.
- 다른 관리자가 먼저 수정한 의뢰는 덮어쓰지 않습니다. 다시 열어 최신 내용을 확인하세요.

## 조건과 보상

조건을 1~6개 지정하면 모두 충족해야 완료됩니다.

| 조건 | 대상 입력 예 |
| --- | --- |
| 일반 몹 처치 | `ZOMBIE` |
| 미씩몹 처치 | 실제 MythicMobs 내부 ID |
| 아이템 제출 | `WHEAT` |
| NPC 만나기 | Citizens NPC 번호 |
| 바이옴 방문 | `minecraft:forest` |
| 직접 연결한 이벤트 | 운영자가 정한 이벤트 ID |

서버/월드를 비우면 모든 곳에서 인정합니다. 서버 이름은 각 백엔드 `quests.yml`의 `server-id`와 일치해야 합니다.
이벤트는 서버에서 `/의뢰관리 event 플레이어 이벤트ID 수량` 또는 기존 `questEvent` API로 진행시킵니다. 클라이언트가 임의로 진행도를 올릴 수 없습니다.
커스텀 아이템의 정확한 데이터를 제출 조건으로 쓸 때는 손에 아이템을 들고 `/의뢰관리 submititem 의뢰ID 목표번호 수량`, `/의뢰관리 reload`를 사용합니다.

- **기숙사 점수**: 수령한 학생의 소속 기숙사에 기존 기숙사 점수를 더합니다. 별도 학점 재화가 아닙니다. 기존 점수판·플레이스홀더에 반영되며, 소속이 없으면 지급을 시작하지 않습니다.
- **돈**: 기존 Vault 경제 플러그인으로 지급합니다.
- **아이템**: 한 줄에 `EMERALD:3` 형식으로 입력, 최대 8종류.
- **추가 보상**: 표시 문구와 실제 실행할 콘솔 명령어를 입력합니다. 명령어는 한 줄씩 최대 8개, 앞의 `/`를 제외하고 `{player}` 또는 `{uuid}`를 사용할 수 있습니다. 표시 문구만 넣으면 실제 보상이 실행되지는 않습니다.

## 반복 횟수와 공개

- 랭크는 F/E/D/C/B/A 중 선택합니다.
- 개인별 클리어 가능 횟수만큼 반복해서 받을 수 있습니다. 포기해도 이전 완료 횟수는 유지됩니다.
- 기본은 누적 횟수입니다. 공개 설정에서 일일 초기화를 선택하면 한국 시간 자정마다 새 횟수를 적용합니다.
- 동시에 진행할 수 있는 의뢰는 3개입니다.
- 한도가 남으면 보상 수령 후 수락 가능 탭으로, 한도를 채우면 완료 탭으로 갑니다. 완료 카드는 종이 전체가 어두워지고 차카데미 도장이 찍힙니다.
- 의뢰당 최대 6개 목표, 전체 최대 64개 의뢰, 페이지당 6개입니다.
- 공개 설정에서 공개 여부와 날짜를 지정합니다. 날짜는 한국 시간 `2026-10-01 18:00` 형식이며, 빈칸은 즉시 공개입니다.
- 즉시 공개: `/의뢰관리 open 의뢰ID`
- 신규 수락 닫기: `/의뢰관리 close 의뢰ID`
- 순서대로 1시간 간격 공개: `/의뢰관리 schedule 3600 의뢰1 의뢰2 의뢰3`
  첫 번째는 즉시, 두 번째부터 지정 간격으로 공개됩니다. 서버가 재시작되어도 지정 시각이 유지됩니다.

이미 수락한 의뢰의 조건·보상은 수락 당시 내용으로 유지됩니다. 편집은 다음 수락부터 적용됩니다. 비공개로 바꾸거나 목록에서 삭제해도 이미 수락한 임무는 계속 수행할 수 있습니다.

## 서버 설치

서버를 종료한 상태에서 이전 `magic-codex-bridge` JAR를 백업하고 0.24.0 JAR로 교체하세요. 클라이언트도 0.32.0이 필요합니다.

`examples/quests.yml`은 새 서버용 예시입니다. 기존 서버의 quests.yml을 덮어쓰지 마세요. 기존 DB와 수락 기록은 자동 호환됩니다. 새 예시 의뢰나 변경된 설명이 기존 운영 목록에 강제로 덮어써지지는 않습니다.

학교/야생/던전의 `database.properties`는 같은 MariaDB를 사용하고, 각 서버 `server-id`는 구분합니다. 관리자 UI 저장은 공용 DB에 바로 반영되며 다른 서버에서 약 5초 이내 갱신합니다. UI로 편집한 해당 의뢰는 편집한 서버의 로컬 YAML에도 저장됩니다.

파일로 수정할 경우 `/의뢰관리 pull`로 공용 최신 목록을 가져온 뒤 수정하고 `/의뢰관리 reload`로 반영하세요. 오래된 다른 서버 파일을 reload하면 최신 편집 내용을 덮어쓸 수 있습니다.

## 검증 범위

서버 단위 테스트 103개, 클라이언트 단위 테스트 174개 통과.
실제 클라이언트에서 GUI 배율 2/3 렌더링 확인.
별도 Paper 서버에서 관리자 저장 패킷 → 의뢰 반복 수락 2회 → 밀 제출 → 아이템 보상 → 기존 기숙사 점수 정확히 14점 합산 → 초과 수락·중복 수령 차단 확인.
MariaDB 별도 스키마와 두 연결로 동시 진행도 갱신, 단일 보상 예약, 반복 횟수 유지, 동일 기숙사 보상 중복 지급 차단 확인.
실제 Velocity 서버 이동, Citizens/MythicMobs 이벤트, 운영 Vault 제공자의 입금은 이번 통합 테스트 범위에 포함되지 않습니다.

지급 중 서버가 중단되어 외부 아이템·명령어·돈 지급 여부가 불명확하면 자동 재지급하지 않고 검토 대기로 남깁니다. `/의뢰관리 audit UUID`로 확인하고, 실제 지급 내역을 확인한 다음 `/의뢰관리 resolve UUID 의뢰ID cycle delivered|retry`로 처리합니다. 기숙사 점수는 학교 DB의 `codex_quest_house_awards`에 지급 토큰별로 기록됩니다.
