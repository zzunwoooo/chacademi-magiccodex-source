# NPC 대화 · 메인 퀘스트 v1

클라이언트 모드 0.33.0 + Paper 플러그인 0.25.0 (Minecraft 1.21.4).
일러스트, 빠른 타자기 출력, 짧은 타자음, 선택지, 대화 기록, 관리자 편집/미리보기, YAML 편집, MariaDB 진행 공유를 제공합니다.

## 설치

- 클라이언트: 기존 Magic Codex 모드 JAR를 새 버전 하나로 교체합니다. 예시 일러스트와 대화창 PNG는 모드에 포함됩니다.
- 서버: 기존 `magic-codex-bridge-*.jar`를 제거하고 새 플러그인 JAR 하나를 `plugins`에 넣은 뒤 재시작합니다. 기존 설정과 데이터는 유지하세요.
- 플러그인이 처음 실행될 때 `plugins/MagicCodexBridge/dialogues/elena.yml`, `arden.yml`을 만듭니다. 이미 있는 파일은 덮어쓰지 않습니다.
- `database.properties`의 기존 MariaDB 설정을 그대로 사용합니다. 학교·야생·던전이 같은 DB를 사용하면 대화 설정과 스토리 진행이 공유됩니다. NPC 연결도 공유하므로 서버별 Citizens 번호 중복에 주의하세요. 서로 다른 번호가 필요하면 별도 대화 ID를 사용하거나 공통 scoreboard 태그를 쓰세요.
- MariaDB 설정이 없으면 `dialogue.db` SQLite로 작동합니다. SQLite 파일을 서버별로 따로 쓰면 서버 간 공유는 되지 않습니다.
- 운영 플러그인 파일은 배포 ZIP으로 제공됩니다. 이 작업에서는 운영 서버 폴더에 자동 덮어쓰지 않습니다.

## 바로 확인하기

관리자(OP):

1. `/대화관리` → 목록, 추가, 편집 창.
2. `/대화관리 preview elena` → 진행에 영향 없는 미리보기.
3. `/대화 elena` → 실제 대화. 첫 선택지로 메인 이야기 시작.
4. `/대화 arden` → 교수를 만나 이야기 완료.
5. `/메인퀘스트` → 현재 이야기와 단계 안내. 의뢰 게시판 위쪽의 **메인 퀘스트**에서도 엽니다.

대사 출력 중 SPACE/대사 클릭은 즉시 완성합니다. 긴 대사는 자동으로 페이지를 나눕니다. 마지막 페이지 이후 선택지가 나타납니다. 숫자 1~6으로도 선택할 수 있습니다. 타자음은 오른쪽 위에서 끌 수 있습니다. 기록은 이번 대화 세션의 최근 80개 장면을 보관합니다.

아르덴은 예시 대사만 준비되어 있으며 일러스트를 비워 두었습니다. 엘레나의 그림을 다른 인물에게 잘못 사용하지 않습니다.

## 관리자 편집

- **대화 정보:** ID, 제목, 공개 여부, 시작 장면, NPC 연결, 권한, 메인 퀘스트 표시 정보.
- **장면 · 대사:** 장면 선택, 이름, 일러스트 ID, 대사. `+ 장면` 버튼으로 ID가 자동 생성됩니다.
- **선택지 · 분기:** 선택지 개수, 문구, 다음 장면. 다음 장면을 비우면 대화 종료.
- **조건 · 동작:** 해당 장면/선택지를 열 조건, 선택했을 때 실행할 동작. 여러 줄은 모두 적용합니다.
- **저장 · 반영:** 공용 DB에 저장하고 로컬 YAML을 내보냅니다. 다른 관리자가 먼저 바꾼 문서는 덮어쓰지 않습니다.
- **미리보기:** 저장 전 초안도 확인할 수 있습니다. 조건을 우회해 모든 분기를 보며 명령어·퀘스트·진행 저장은 실행하지 않습니다.

문서당 장면 32개, 장면당 선택지 6개, 대사 1,600자, 문서 약 26KB입니다. 이야기가 커지면 NPC/챕터별로 파일을 나누고 공통 `story`/`flag`로 연결하세요. 수정 전 YAML은 `.bak`으로 백업됩니다. 연결이 남아 있는 장면을 삭제하면 저장 시 오류를 알려줍니다.

## NPC 연결

대화 정보의 NPC 연결 칸에 한 줄씩 입력합니다.

```text
citizens:12
tag:codex_elena
```

Citizens NPC 12번을 우클릭하거나, `codex_elena` scoreboard 태그를 가진 일반 엔티티를 우클릭하면 대화가 열립니다. 실제 NPC는 운영자가 원하는 위치에 만들어 연결하세요. 예시 설정은 `tag:codex_elena`, `tag:codex_arden`입니다. 태그 방식은 바닐라 엔티티에 사용하며 Citizens 엔티티는 `citizens:번호`로 연결합니다.

대화 가능 거리는 8블록입니다. 다른 월드로 이동하거나 NPC가 사라지면 선택을 거부합니다. 한 NPC에 여러 대화를 중복 연결하기보다는 하나의 시작 장면에서 조건부 선택지로 분기하는 구성을 권장합니다. 관리자 `/대화 <ID>` 명령은 NPC 없이 실제 흐름을 확인하는 용도입니다.

## YAML 편집

1. `/대화관리 pull elena`로 최신 공용 설정을 로컬 파일에 가져옵니다.
2. `plugins/MagicCodexBridge/dialogues/elena.yml`을 편집합니다.
3. `/대화관리 reload elena`로 검증 후 공용 반영합니다.

새 YAML은 파일명(영문 ID)을 정하고 `/대화관리 reload 파일명`으로 등록합니다. 인게임 편집과 YAML 모두 같은 검증을 거칩니다. 나머지 서버는 최대 약 10초 안에 공용 설정을 가져옵니다. DB 직접 수정 시 revision을 빠뜨리기 쉬우므로 외부 편집은 YAML을 사용하세요.

## 조건

```text
flag met_elena yes
not-flag met_arden yes
story first_clue find_arden
permission magiccodex.ascend.3
quest forest_patrol active
quest forest_patrol completed
custom circle_at_least 3
```

- `flag`: 값 일치. `not-flag`: 값이 다르거나 아직 없음.
- `story`: 해당 메인 이야기의 단계가 일치.
- `permission`: 서버 권한 검사.
- `quest`: 기존 의뢰의 현재 주기에서 진행 중/1회 이상 완료했는지 확인. 일일 의뢰는 다음 날 다시 평가됩니다.
- `custom`: 서버 플러그인이 등록한 조건 함수. 등록되지 않았으면 통과하지 않습니다.
- 모든 조건을 만족해야 표시/실행됩니다. 클라이언트가 판정하지 않습니다.

## 선택 동작

```text
flag met_elena yes
story first_clue find_arden
quest forest_patrol
event spoke_to_elena
command give {player} minecraft:emerald 1
custom unlock_spell spark
```

`quest`는 기존 의뢰를 수락합니다. 의뢰 권한·공개 시각·수락 한도는 그대로 적용됩니다. `event`는 기존 의뢰의 EVENT 목표에 1회 진행을 전달합니다. `command`는 서버 콘솔 권한으로 실행되므로 관리자만 작성합니다. `{player}`, `{uuid}`를 지원합니다. 기숙사 점수/아이템/돈은 기존 의뢰 보상을 활용하거나 검증된 서버 명령어를 연결하세요.

**중복 실행:** `quest/event/command/custom`은 플레이어별 `대화ID:장면ID:선택지번호`를 기준으로 한 번 실행합니다. 같은 선택지 재클릭/재접속으로 재지급하지 않습니다. 재사용할 반복 보상은 의뢰의 반복 기능으로 구성하세요. 발행 후 보상 선택지 번호를 다른 보상 용도로 바꾸지 마세요. 새 동작은 새 장면 ID로 추가하면 구분됩니다. `flag/story` 값 변경은 선택 때마다 적용되므로 완료 단계로 되돌아갈 수 없는 조건을 직접 설정하세요.

## 오류 복구

외부 명령어는 DB와 하나의 트랜잭션으로 묶을 수 없습니다. 실행 직전 기록을 저장하고, 크래시/실패로 결과가 모호하면 **자동 재지급하지 않고 검토 대기**로 둡니다. 단계/플래그는 이미 저장되어 있을 수 있으므로 관리자는 지급 결과와 진행 상태를 함께 확인해야 합니다.

```text
/대화관리 audit <플레이어UUID>
/대화관리 resolve <플레이어UUID> <토큰>
```

누락된 처리는 운영자가 확인 후 보완하고 `resolve`로 확인 완료 처리합니다. resolve 자체는 보상을 다시 실행하지 않습니다. 검토 대기가 남아 있는 플레이어는 실제 대화 진행을 막아 후속 분기 오류를 방지합니다.

## 일러스트와 확장 API

PNG 위치: `assets/magiccodex/textures/gui/dialogue/<일러스트ID>.png`. 기본은 투명 배경 1024×1536의 2:3 비율입니다. 현재 배치는 위쪽부터 허벅지까지 그린 초상을 기준으로 합니다. 예: `elena-neutral` → `elena-neutral.png`. 표정마다 새 ID를 만들고 장면에서 바꿉니다. 추가 리소스는 모드/클라이언트 리소스팩에 포함해 배포하고 F3+T 또는 재시작으로 불러옵니다. 임의 URL 다운로드는 하지 않습니다.

다른 서버 플러그인은 MagicCodexBridge 이후 활성화한 뒤 서버 메인 스레드에서 등록할 수 있습니다.

```java
bridge.registerDialogueCondition("circle_at_least", (player, argument) -> {
    return player.hasPermission("magiccodex.ascend." + Integer.parseInt(argument));
});
bridge.registerDialogueAction("unlock_spell", (player, argument) -> {
    // 서버의 기존 마법 등록 API 등 호출
});
```

함수는 메인 스레드에서 호출됩니다. 블로킹 DB/HTTP/파일 읽기를 넣지 말고 이미 확보한 서버 상태를 사용하세요. `custom` 동작은 동기 완료 계약입니다. 별도 비동기 처리가 필요한 시스템은 그쪽에서 멱등성과 실패 복구를 구현한 진입점을 연결해야 합니다.

## 성능 및 저장

- 서버는 클릭한 선택지만 받아 세션 토큰·순서·조건·거리·권한을 재검사합니다. 타자 연출 패킷을 보내지 않습니다.
- 단일 IO 작업자와 대기열 상한, 플레이어별 연타 제한. 모든 런타임 DB/YAML IO는 비동기입니다.
- 설정은 캐시하며 10초 간격으로 갱신합니다. 모든 플레이어 진행을 주기적으로 읽지 않습니다.
- MariaDB의 revision 비교로 서버 간 동시 선택을 차단합니다. 완료한 상태 변경 이후 이동한 서버가 최신 진행을 읽습니다.
- 클라이언트는 완성된 대사 줄 텍스처를 캐시하고 표시 범위만 넓힙니다. 프레임마다 새 글자 이미지를 만들지 않습니다.
- DB 테이블: `codex_dialogue_catalog`, `codex_story_state`, `codex_dialogue_effect`. 기존 펫·인벤토리·외부 플러그인의 저장은 수정하지 않습니다.

## 검증

서버 108개 / 클라이언트 174개 단위 테스트 통과. 별도 Paper 서버 + 실제 클라이언트에서 관리자 저장, 초안 미리보기, 실제 대화 분기, 이야기 단계 저장, 중복 패킷·반복 선택의 명령어 1회 실행, 이야기 표시를 확인했습니다. 별도 MariaDB에서 두 연결의 동시 선택·진행 공유·외부 동작 중복 차단을 확인했습니다. GUI 배율 2/3의 실제 렌더링 스크린샷도 포함합니다.

운영 Citizens NPC 우클릭과 실제 Velocity 이동 경로는 운영 배치 이후 연결 확인이 필요합니다. 현재 예시 검증은 관리자 대화 명령으로 진행했습니다.
