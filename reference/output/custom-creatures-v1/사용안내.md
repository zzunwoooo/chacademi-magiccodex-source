# 커스텀 야생 몹·펫 1차 파일

## 구성

- 대상 138개 항목. 기본 모델 137개(일반/우두머리 버팔로 모델 공유).
- ModelEngine: 일반 137 + 이로치 전용 137 = 274개 `.bbmodel`.
- MythicMobs: 야생 일반/이로치 276 + 펫 일반/이로치 276 = 552개 정의.
- MCPets: 일반/이로치 펫 276개. 소유권 permission은 서로 분리.
- MagicCodexBridge: `taming.d/custom_creatures.yml`과 `pets.d/custom_creatures.yml`에 교화·1~3성 매핑.
- 클라이언트: `config/magiccodex/pets/models`에 펫 도감용 모델 276개.

원본 압축파일과 기존 플러그인 설정은 수정하지 않았다. 배포 파일은 이 폴더에 준비했으며 실제 서버·런처에 자동 설치하지 않았다.

## 이로치

v3에서는 검은색 중심 조합을 137개 기본 모델 중 7개로 제한했다. 흑백/흑금 외에는 산호·민트·청옥·하늘·호박·장미·라일락·올리브 등 몹별 지정 팔레트로 분산했다. 같은 모델 계열의 변형도 서로 다른 주조색을 사용한다. 무채색 영역도 몸색과 연결하여 대부분 은색으로 수렴하던 현상을 줄였다. 새싹 5종은 기존 이로치를 유지했다. UV·알파·해상도·형상·애니메이션은 유지한다. 원본의 색 영역을 분석한 재배색이며, 각 부위를 손으로 다시 그린 작업은 아니다.

이름은 일반형과 같다. 접두사 ‘이로치’는 붙이지 않으며 노란색 `§e`로 표시한다. 월드 이름, 교화 대상 UI, 펫 도감 이름에 반영했다. 기존 반짝임·주기적 효과음 처리를 사용한다.

신규 프로필은 `roll-shiny: false`이므로 자동 이로치 추첨을 추가하지 않았다. 일반형/이로치형을 명령으로 각각 소환할 수 있고, 기존 `/이로치관리 지정`·`해제`로 바라보는 야생 개체의 전용 모델을 전환할 수 있다. 기존 바닐라 이로치 출현 설정은 변경하지 않았다.

## 애니메이션과 행동 범위

기존 공격 동작 47개와 피격 동작 1개를 재사용했다. 공격이 없는 모델 90개에는 짧은 고개 움직임, 피격이 없는 모델 136개에는 짧은 몸 반동을 추가했다. 원래 애니메이션 트랙은 유지했다. 작은 새에는 누락된 히트박스도 추가했다.

이번 파일은 초기 야생형 템플릿이다. 온순/반격/선공과 기본 이동·공격을 분리했고, 소환 펫에는 공격 스킬과 적대 타깃을 넣지 않았다. 기존 보스팩의 복잡한 원거리 기술·투사체·페이즈 전체를 이식한 것은 아니다. 기본 공격 이벤트에 기존 동작을 연결했으며, 긴 원본 공격 동작의 정확한 타격 프레임·개별 비행/수중 경로·71개 탑승 후보의 좌석은 인게임 조정 대상이다. 원본 mount 본이 있는 모델만 탑승 허용으로 설정했다.

드롭은 비워뒀다. 랜덤 스폰 파일·스폰 가중치·바이옴 생성 데이터팩은 추가하거나 수정하지 않았다. 서식지·확률·별은 앞서 만든 기획안을 사용한다.

## 파일 적용

1. 현재 서버와 리소스팩을 백업한다.
2. `server/plugins`의 신규 설정·blueprints를 서버 plugins 아래에 병합한다. 기존 MagicCodexBridge JAR는 0.26.0으로 교체하고 구버전 JAR를 함께 두지 않는다.
3. 별도 설치된 MythicMobs 5.9.0, ModelEngine 4.0.8, MCPets 4.1.11, LuckPerms를 사용한다. 이들 상용/외부 플러그인 JAR는 배포 ZIP에 포함하지 않는다.
4. 서버를 재시작해 ModelEngine 리소스팩을 생성하고 기존 서버 리소스팩에 병합·배포한다. blueprints만 복사하고 생성된 리소스팩을 적용하지 않으면 모델이 보이지 않는다.
5. `client/config`를 런처 인스턴스의 `config` 아래에 병합한다. `client/mods`의 0.34.0 모드로 기존 버전을 교체한다. 모드는 클라이언트 전용이다.
6. 기존 `taming.yml`, `pets.yml`은 덮어쓰지 않는다. 새 플러그인이 `.d` 폴더를 추가로 읽는다. 중복 키는 조용히 덮어쓰지 않고 오류로 알려준다.

## 수동 소환 예시

게임 내 관리자 기준:

```text
/mm mobs spawn CA_Wild_squirrel
/mm mobs spawn CA_Wild_squirrel_shiny
/mm mobs spawn CA_Wild_ogre_club
/mm mobs spawn CA_Wild_glacialcore_shiny
```

`manifest.json`에 모든 야생 ID, 펫 ID, 모델 ID가 있다. MCPets 도감에 표시되더라도 소유권이 없으면 소환할 수 없도록 설정했다. 정상적인 획득은 `/교화`를 사용한다. 보스는 기존 사망 유예 상태에서만 교화 가능하다.

## 검증 범위

- 플러그인 111개, 클라이언트 174개 단위 테스트 통과. Gradle 테스트 워커의 환경 오류는 기존 독립 JUnit 실행기로 검사했다.
- 일반/이로치 137쌍, 텍스처 197쌍의 형상·UV·애니메이션·알파·해상도 보존 검사.
- 격리된 Paper 1.21.4 서버에서 MCPets 276개 등록, 대표 야생 개체 18개 소환과 모델 부착, 노란 이름, 교화의 이로치 펫 ID 선택, 일반↔이로치 모델 전환 검사.
- 실제 플레이어 조작으로 모든 개체의 움직임·전투·라이딩을 확인한 것은 아니다. HTML은 정지 자세의 외형 비교용이다.

`animation-audit.json`, `애니메이션-점검표.md`, `color-audit.json`, `validation.json`에 세부 기록이 있다. HTML 도감의 ‘일반 외형’ 버튼을 누르면 이로치 전용 모델로 비교할 수 있다.
