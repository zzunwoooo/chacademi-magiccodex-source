# 차카데미아 마나 연동

서버: MagicCodexBridge **0.6.0** / 클라이언트: Magic Codex **0.13.0**, Fabric 1.21.4.

## 서버 설치

서버를 종료하고 기존 MagicCodexBridge JAR을 0.6.0으로 교체한 뒤 시작합니다. 같은 플러그인의 이전 JAR을 함께 두지 않습니다.
기존 권한·Vault 연동 설정은 유지됩니다. PlaceholderAPI가 설치되어 있으면 플레이스홀더가 자동 등록됩니다.
처음 시작하면 `plugins/MagicCodexBridge/mana-spells.yml`이 생성됩니다. 현재 마법 200종 중 명령이 있는 195종은 활성화되어 있고, 명령이 없거나 패시브로 지정된 5종은 비활성화되어 있습니다.

## 기본 수치와 저장

신규 플레이어는 마나 100/100, 초당 회복량 5로 시작합니다. 기존 플레이어도 마나 저장 데이터가 없으면 이 기본값으로 시작합니다.
`config.yml`에 다음 항목을 추가하면 신규 플레이어 기본값을 바꿀 수 있습니다. 기존 설정 파일에 없어도 위 기본값을 사용합니다.

```yaml
mana:
  default-maximum: 100
  default-regeneration: 5
```

회복은 서버의 단일 20틱 작업으로 진행합니다. 정상 TPS에서 1초이며 서버가 느려지면 실제 시간 기준 회복도 느려집니다. 사망 중·오프라인에는 회복하지 않습니다.
현재 마나·기본 최대량·기본 회복량은 플레이어 데이터(PDC)에 저장됩니다. 재접속과 정상 서버 재시작에 유지되며, 접속을 끊어도 저장된 쿨타임이 남습니다.
플러그인은 직접 파일을 매초 쓰지 않습니다. PDC를 주기적으로 갱신하고 시전·관리자 변경·퇴장·종료에도 갱신합니다. 실제 디스크 저장은 Minecraft의 플레이어 저장 주기를 따릅니다.

## 관리자 명령

콘솔 또는 `magiccodex.mana.admin` 권한(기본 OP)이 필요합니다. 대상은 접속 중인 플레이어입니다.

| 명령 | 기능 |
| --- | --- |
| `/codexmana get 닉네임` | 현재·최대·초당 회복 조회 |
| `/codexmana set 닉네임 50` | 현재 마나를 50으로 설정 |
| `/codexmana add 닉네임 20` | 현재 마나 20 추가. 음수로 차감 가능 |
| `/codexmana max 닉네임 200` | 기본 최대 마나를 200으로 설정 |
| `/codexmana regen 닉네임 7.5` | 기본 초당 회복량을 7.5로 설정 |
| `/codexmana refill 닉네임` | 현재 최대량까지 회복 |
| `/codexmana reload` | 기본 설정·서버 마법 비용 목록 다시 읽기 |

최대량을 높여도 현재 마나를 자동으로 채우지 않습니다. 최대량을 낮추면 현재 마나는 새 최대량 이하로 제한됩니다. reload는 이미 저장된 플레이어 기본 수치를 덮어쓰지 않습니다.

## 스테이터스창용 PlaceholderAPI

| 플레이스홀더 | 값 |
| --- | --- |
| `%magiccodex_mana_current%` | 현재 마나 |
| `%magiccodex_mana_max%` | 장비·버프 보정이 포함된 최대 마나 |
| `%magiccodex_mana_regen%` | 보정이 포함된 초당 회복량 |
| `%magiccodex_mana_percent%` | 남은 마나 비율 0~100 |

최대 소수 둘째 자리까지 표시하며 불필요한 `.0`은 붙이지 않습니다. 오프라인 플레이어는 빈 문자열을 반환합니다. 읽기는 캐시된 값만 사용하며 파일·Vault·권한 조회를 발생시키지 않습니다.

## 마법 시전과 비용

모드는 마법 ID만 전송합니다. 서버는 `mana-spells.yml`의 권한·마나·쿨타임·명령어를 사용합니다. 클라이언트 YAML의 비용을 바꿔도 서버 비용은 바뀌지 않습니다.
마나 또는 권한이 부족하거나 쿨타임 중이면 시전을 거절합니다. 모드는 승인 응답이 도착한 뒤 화면 VFX·사운드·쿨타임을 시작합니다.
등록된 같은 명령을 채팅으로 직접 입력해도 마나 검사를 거칩니다. 별도의 명령 별칭이나 다른 플러그인이 내부에서 스킬을 직접 실행하는 경로는 아래 API로 연결해야 합니다.
명령 자체가 없거나 명령 실행이 실패를 반환/예외 발생하면 차감을 취소합니다. 명령은 성공으로 반환했지만 MythicMobs/Skript 내부 조건 때문에 효과가 발생하지 않은 경우는 자동 판별하지 못합니다. 해당 스킬의 내부 성공 판정·환불은 서버 스킬 구현 때 연결해야 합니다.

앞으로 마법의 비용·쿨타임·권한·명령을 수정하면 **클라이언트 YAML과 서버 `mana-spells.yml`을 함께 갱신**해야 합니다. 서버 목록은 자동으로 클라이언트 값을 신뢰하거나 덮어쓰지 않습니다.
현재 JAR에는 마나 관리와 시전 연결이 들어 있습니다. 200종의 실제 MythicMobs 스킬을 새로 구현한 것은 아닙니다. 아직 없는 `/마법 ...` 명령은 실패 안내가 나오며 비용은 소비하지 않습니다.

## 장비·다른 플러그인용 API

```java
ManaService mana = Bukkit.getServicesManager().load(ManaService.class);
mana.snapshot(player.getUniqueId()); // Optional<Snapshot>: current, maximum, regeneration
mana.tryConsume(player.getUniqueId(), 30); // 성공한 경우에만 true와 함께 차감
mana.add(player.getUniqueId(), 20);
mana.setBaseMaximum(player.getUniqueId(), 100);
mana.setBaseRegeneration(player.getUniqueId(), 5);
mana.setModifier(player.getUniqueId(), "wand:equipped", 100, 2); // 최대 +100, 회복 +2
mana.removeModifier(player.getUniqueId(), "wand:equipped");
```

`school.magiccodex.paper.ManaService`를 사용합니다. 조회 스냅샷은 다른 스레드에서도 읽을 수 있고, 변경은 서버 메인 스레드에서만 호출해야 합니다. 등록 전·미접속 플레이어의 변경은 허용하지 않습니다.
동일한 보정 키는 교체되어 중복 누적되지 않습니다. 장비·버프 보정은 일시적인 값으로 저장하지 않으므로 해당 장비 플러그인에서 접속·장착 변경 때 다시 적용합니다.
Bridge가 이미 비용을 차감하는 시전 경로에 `tryConsume`을 또 붙이면 중복 차감됩니다. 스킬 내부에서 별도로 차감할 경우 해당 Bridge 비용을 0으로 두는 등 차감 책임을 한 곳으로 정합니다.

## 확인 순서

1. 서버에 JAR을 교체하고 접속합니다. HUD에 기본 100/100이 보이는지 확인합니다.
2. `/codexmana set 닉네임 20` 실행 후 정상 TPS에서 초당 5씩 회복하는지 봅니다.
3. `/codexmana max 닉네임 200`, `/codexmana regen 닉네임 7.5`를 실행해 HUD·플레이스홀더를 확인합니다.
4. 서버에서 실제 동작하는 마법 명령을 설정하고, 충분한 마나와 부족한 마나 상태에서 각각 시전합니다.
5. 재접속 후 현재 마나와 기본 수치가 유지되는지 확인합니다.

빌드·자동 테스트는 완료했습니다. 사용자 서버의 실제 MythicMobs/Skript 조합에 연결한 접속 테스트는 서버에 설치한 뒤 진행해야 합니다.
