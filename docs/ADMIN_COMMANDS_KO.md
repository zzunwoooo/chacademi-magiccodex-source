# 한국어 관리자 명령어

## 유저 관리

접속 중인 영문 계정명 또는 유일한 표시 닉네임으로 지정한다. 중복 표시 닉네임은 거부하므로 영문 계정명을 사용한다. 등록된 마법·칭호·NPC는 정확한 ID 또는 유일한 표시 이름만 허용한다.

- `/유저관리 <유저> 스탯 현재마나|마나|마나회복|마법가속 설정|추가|감소 <수치>`
  - `마나`: 장비·버프를 제외한 기본 최대 마나. 회복과 가속도 기본 수치에 적용한다.
  - 현재마나는 실제 최대 마나를 넘을 수 없다. 감소 결과는 0이 하한이다. 기본 스탯은 0~1,000,000 범위이며 상한 초과는 거부한다.
- `/유저관리 <유저> 마법 습득|미습득 <등록 마법명 또는 ID>`
  - 서버가 로드한 마법 등록 카탈로그 전체(현재 299개)의 정확한 ID·권한을 사용한다. 시전 비활성 마법도 소유 상태는 관리할 수 있으나 시전 활성화 설정은 바꾸지 않는다.
  - MagicDiscovery의 저장된 습득 상태와 권한을 함께 갱신한다. 미습득 전환은 최초 획득·최초 보상 이력을 삭제하지 않는다. 재발견은 기존 보상을 중복 지급하지 않는다.
  - 대상 마법의 누적 조건은 새 행동으로 다시 채운다. 접속·주기 검사만으로 즉시 복귀하지 않는다. 상태 전용·선행 마법 전용 조건은 성공한 시전 또는 명시적으로 검증된 상태 이벤트에서 다시 평가할 수 있다. 관리자 습득 자체는 최초 발견 보상을 새로 만들지 않는다.
  - 자연 발견 조건이 아직 없는 등록 마법은 관리자 습득/미습득만 관리하며, 새 획득 조건을 임의로 만들지 않는다. 기존 발견 전용 옛 ID를 시전 ID와 이름으로 추측 연결하지 않는다.
- `/유저관리 <유저> 기숙사 <기숙사명>`
- `/유저관리 <유저> 호감도 <등록 NPC명 또는 ID> 조회`
- `/유저관리 <유저> 호감도 <등록 NPC명 또는 ID> 설정|추가|감소 <0 이상 정수>`
  - 활성 ChacaNPC 캐릭터 카탈로그를 사용한다. 알 수 없거나 중복된 이름으로 임의 기록을 생성하지 않는다.
  - 관리자 변경은 일일 변화량 제한을 사용하지 않는다. 기존 하트 단계·호칭은 유지되며 점수 범위는 0~min(100, 20×(하트+1))이다.

권한은 기존 `magiccodex.mana.admin`, `magicdiscovery.admin`, `magiccodex.school.admin`, `magiccodex.dialogue.admin`을 각 기능에 그대로 적용한다.

## 기숙사 점수

- `/점수관리 <기숙사> 조회`
- `/점수관리 <기숙사> 추가|감소|설정 <점수>`

추가·감소 인수는 0 이상의 정수다. 설정은 기존 점수 저장소와 동일하게 -1,000,000,000~1,000,000,000을 허용한다. 추가·감소 결과가 이 범위를 넘으면 저장하지 않는다. 기존 `magiccodex.school.admin` 권한을 사용한다.

## 아이템 지급

게임 안에서 실행한 관리자 자신에게 1개 지급한다. 인벤토리가 가득 차면 거부한다.

- `/아이템관리 마법봉 <마력> <추가마나> <마법가속>`
  - 각 능력치 0~100,000. 새 마법봉의 강화 전 기본 수치도 함께 기록한다.
- `/아이템관리 마력코어 <코어수> <성공률%> <별잡기보너스%> <능력치상승배율> <마력|마나|마법가속>`
  - 코어수 1~10, 성공률·보너스 0~100%, 상승배율 0 초과~10,000.
  - 예: `/아이템관리 마력코어 3 50 10 1 마력`은 감정 완료된 3코어, 기본 성공률 50%, 별잡기 성공 시 10%p 보너스, 기존 강화 설정의 능력치 증가량 1배다.
  - 내부에는 성공률을 0~1로 저장한다. 기존 강화·재구성·툴팁과 같은 아이템 키를 사용한다.

기존 `magiccodex.enhance.admin` / `magiccodex.core.admin` 권한을 사용한다. 탭 완성에는 다음 인수의 의미와 범위가 표시된다. 꺾쇠로 표시한 안내는 실제 수치로 바꿔 입력한다.

## 칭호

- `/칭호추가 <유저> <등록 칭호명 또는 ID>`: 활성 카탈로그 칭호만 지급
- `/칭호삭제 <유저> <등록 칭호명 또는 ID>`: 카탈로그에 존재하는 칭호만 회수. 비활성 칭호도 정리 가능

임의 문장을 입력해 새 칭호를 만들지 않는다. 기존 `magiccodex.titles.admin` 권한을 사용한다. 칭호 삭제 시 선택 중인 접두·접미 칭호도 기존 저장소 규칙대로 해제된다.

## 멈춘 거래·수령·대화·의뢰 보상 처리

유저 인수는 접속 중인 닉네임·영문 계정명 또는 UUID다(접속하지 않은 유저는 UUID). 모든 처리는 서버 로그에 `SHOP ADMIN` / `MAIL ADMIN` / `DIALOGUE ADMIN` / `QUEST ADMIN` 으로 남는다(관리자, 유저, 기록 ID, 처리 방법).
자동으로 판정할 수 있는 기록은 유저가 접속하거나 상점·우편함·대화를 열 때 스스로 정리되므로, 아래 명령은 목록에 "확인 필요"로 남은 것에만 쓴다.

### 상점 (`magiccodex.shop.admin`)

- `/상점 <상점ID>`: 관리자 전용. 유저는 상인 NPC를 눌러 상점을 연다(권한 `magiccodex.shop`, 기본 허용).
- `/상점관리 기록 <유저|UUID>`: 끝나지 않은 거래(구매/판매, 상태, 상품·수량·합계, 상점, 시각, 거래한 서버)와 권장 처리 방법을 보여 준다.
- `/상점관리 처리 <거래ID> 완료|환불|취소`
  - `완료`: 구매는 "돈이 빠져나간 것"으로 보고 상품을 우편으로 지급한 뒤 닫는다(우편은 거래마다 한 통만 생긴다). 판매는 "대금이 이미 지급된 것"으로 보고 기록만 닫는다.
  - `환불`: 구매는 합계 금액을 돌려주고, 판매는 팔려던 아이템을 우편으로 돌려준 뒤 실패로 닫는다. 도중에 멈추면 `환불 처리 중(refunding)`으로 남고 같은 명령을 다시 실행하면 이어서 끝낸다(아이템 우편은 중복되지 않는다. 돈은 로그의 `SHOP ADMIN REFUND PAID` 줄이 있으면 이미 지급된 것이므로 `취소`로 닫는다).
  - `취소`: 아무 보상 없이 실패로 닫는다(돈·아이템이 움직이지 않았음을 확인한 경우).
  - 구매 `prepared`(출금 전)는 돈이 빠져나가지 않은 것이 보장되므로 `완료`·`환불`을 거부하고 `취소`만 받는다(상품·돈이 공짜로 나가는 것을 막기 위함). 서버 기록이 없는 옛 구매 기록은 출금 여부를 알 수 없어 예전처럼 세 가지 모두 가능하다. 판매 `prepared`는 아이템 회수 전후를 기록만으로 알 수 없어 `환불`·`취소`·`완료`를 그대로 받는다(아이템이 사라졌으면 환불, 그대로면 취소).
- 자동 처리되는 상태: 구매 `prepared`(출금 전 → 자동 실패), 구매 `paid`(우편 자동 재발송), 거래한 서버에서의 판매 `prepared`/`sale_removed`(아이템 회수 영수증으로 판정 → 자동 지급 또는 자동 실패).
- 관리자 확인이 필요한 상태: 구매 `paying`(출금 직전·직후), 판매 `credit_pending`(입금 직전·직후), `refunding`, 서버 기록이 없는 옛 기록. 로그의 `SHOP REVIEW order=<거래ID>` 줄에 무엇이 실행됐는지 적혀 있다.

### 우편 (`magiccodex.mailbox.admin`, 기본 op)

- `/우편관리 기록 <유저|UUID>`: 수령 도중 멈춘 첨부(수령번호, 우편 제목, 아이템, 수령하던 서버).
- `/우편관리 처리 <유저|UUID> <수령번호> 완료|반환`
  - `완료`: 유저가 아이템을 이미 받았다 → 수령 완료로 닫는다(다시 주지 않음).
  - `반환`: 받지 못했다 → 우편함에서 다시 수령할 수 있게 되돌린다.
- 수령하던 서버에서 유저가 우편함을 열면 영수증 유무로 자동 판정하므로, 보통은 유저를 그 서버로 보내는 것으로 충분하다.

### 대화 (`magiccodex.dialogue.admin`)

- `/대화관리 audit <유저|UUID>`: 끝나지 않은 대화 동작(토큰, 대화:장면:선택지, 상태, 남은 동작 목록).
- `/대화관리 resolve <유저|UUID> <토큰>`: 그 기록의 남은 동작을 보여 주고 처리 방법을 묻는다.
- `/대화관리 resolve <유저|UUID> <토큰> rerun`: 남은 동작을 다시 실행 대기로 돌린다. 유저가 이 서버에 접속해 있으면 바로 실행하고, 아니면 다음 접속·대화 열기 때 실행한다.
- `/대화관리 resolve <유저|UUID> <토큰> done`: 남은 동작을 실행하지 않고 완료로 닫는다.
- 상태: `queued`(대기 — 자동 실행), `running`(실행 도중 서버가 멈춤 — 실행 여부 불명), `review`(동작 실패 — 목록 맨 위 동작부터 실행되지 않음), `pending`(옛 버전 기록 — 실행 여부 불명). 확인이 필요한 기록은 그 대화만 막고 다른 대화는 계속 진행된다.

### 의뢰 보상 (`magiccodex.quests.admin`)

- `/의뢰관리 audit <유저|UUID>`: 보상 지급 도중 멈춘 의뢰(id, cycle, 토큰)와 "지급함 / 남음" 단계를 보여 준다.
- `/의뢰관리 resolve <유저|UUID> <id> <cycle> delivered|retry|reset`
  - `delivered`: 지급 완료로 닫는다(추가 지급 없음).
  - `retry`: 기록상 아직 주지 않은 단계만 지급하고 완료한다(아이템 → 돈 → 보상 명령어 → 기숙사 점수). 유저가 이 서버에 접속해 있어야 한다. 단계 기록이 없는 기록(지급 도중 서버가 멈춤)은 retry 할 수 없다.
  - `reset`: 수령 전 상태로 되돌린다. 유저가 보상을 처음부터 전부 다시 받을 수 있으므로, 아무 것도 지급되지 않았음을 확인했을 때만 쓴다. (예전 `retry` 의 동작이다.)
- 보상 명령어가 실패해도 의뢰는 완료되며 로그에 `QUEST REWARD COMMAND FAILED quest=… player=… command=[…]` 로 남는다. `/의뢰관리 reload`·편집 화면 저장·`rewardcommand` 때 이 서버에 없는 명령어는 경고로 알려 준다.

## 공개 명령 이름 정리

`codex*` 공개 명령·별칭을 제거했다. `계절관리`, `펫관리`, `온도관리`, `마나관리`를 사용한다. `마나관리 새로고침`은 설정만 다시 읽으며 유저 수치 수정은 `유저관리`에서 한다. 승급 명령은 `/클래스승급`, 발견 통합 관리 명령은 `/마법발견관리`다. 내부 namespace, 영속 데이터 키, 기존 권한 키는 변경하지 않는다.

## 검증 메모

순수 입력 규칙·카탈로그·명령 등록·능력치·호감도 동시 갱신·발견 이력 보존 테스트를 추가했다. 이 문서 작성 시점에는 클라우드에서 소스와 diff만 검토했으며, Gradle 빌드/테스트는 별도 호스팅 검증 대상이다. 실게임 채팅·탭 완성·재접속·장비 보너스·권한 동기화는 통합본에서 확인해야 한다.

### 호스팅 수동 확인

1. 기존 권한으로 각 분기 실행/거부가 맞는지, 영문 계정·한글 닉네임·동명이인·공백 포함 이름 및 숫자 인수 탭을 확인한다.
2. 장비를 착용한 상태에서 기본 마나를 변경한 후 탈착·재접속에도 기본값과 보너스가 중복되지 않는지 확인한다.
3. 마법을 자연 발견하고 보상을 수령한 후 미습득 → 재접속 → 조건 재수행 → 재습득을 확인한다. 최초 보상은 중복되지 않아야 한다.
4. NPC 호감도 변경 전후 하트·호칭·선물/대화 일일 한도가 유지되는지 확인한다.
5. 생성된 마법봉·코어를 기존 감정/강화/재구성/툴팁에서 읽고 사용할 수 있는지 확인한다. 가득 찬 인벤토리에서는 지급이 거부되어야 한다.
6. 비활성·미등록 칭호 지급을 거부하고, 선택 중인 등록 칭호 회수 후 표시가 해제되는지 확인한다.
