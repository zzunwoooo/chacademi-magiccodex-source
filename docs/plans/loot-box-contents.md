# 뽑기 상자 내용 — 가구 · 낚시도구 · 몬스터 전리품 뽑기권 (2026-10-26, 오너 검수 대기)

뽑기 상자(API 상자, [FINAL_PATCHES §36](../handoff/CLAUDE_OPENING_FINAL_PATCHES_20261026.md)) 에 뽑기권 상자 3개를 미리 넣었다 ([§37](../handoff/CLAUDE_OPENING_FINAL_PATCHES_20261026.md)).
**API 상자 2종(`api_box_normal`·`api_box_premium`)은 오너가 직접 만든다 — 여기 없음.**

- 파일: `magic-codex-paper/src/main/resources/loot-boxes.yml` (jar 기본값) = `deployment/operating-config/MagicCodexBridge/loot-boxes.yml` (운영 overlay, 같은 내용).
- 세 상자 모두 `enabled: true`, 열쇠 = 아래 ItemsAdder id. **확률(weight)은 전부 오너 검수 대기.**
- 확률 = 가중치 ÷ 그 상자 가중치 합. 바꾸는 법: `/상자관리 관리 <이름>` 창에서 가중치 고치기 (또는 yml 고치고 `/상자관리 새로고침`). 창에서 저장하면 yml 의 주석은 지워진다(머리 주석만 남음).
- 확인: `/상자관리 확률 <이름>` (채팅 확률 표), `/상자관리 테스트 <이름> 10` (소모·지급 없는 미리보기).

## 오너 검수 항목

1. **가구** — ① 특수 가구 8종(연금 작업대·빗자루 거치대·아티팩트 진열장·거울 옷장·펫 쿠션·큐디치 트로피장·기숙사 점수판·내 정보 액자)을 일반 가구와 **같은 확률로 넣음** ② **미끼 상자 3종은 뺌** ③ 이미 가진 가구는 **다시 뽑기** (아래) ④ 전부 일반 등급색. 다 맞는지.
2. **낚시도구** — 등급 묶음 확률 **일반 60 · 고급 28 · 유일 10 · 전설 2 %** 와 미끼 개수(일반 10 · 고급 5 · 유일 3 · 전설 1개)가 괜찮은지. 기본 세트 4종(대나무 낚싯대·코르크 찌·무명실 낚싯줄·지렁이)을 넣어도 되는지(꽝처럼 느껴질 수 있음).
3. **몬스터 전리품** — 별 묶음 확률 **1성 70 · 2성 24 · 3성 6 %** 와 개수(1성 8 · 2성 3 · 3성 1개). **보상 아이템 자체가 임시**(아래 "추정") — 야생 몹 전용 전리품 아이템을 정하면 바꿔야 함.
4. 세 뽑기권 ItemsAdder id(`item:furniture_ticket`·`item:fishing_ticket`·`item:monster_loot_ticket`)가 운영 ItemsAdder 의 실제 id 와 같은지 (다르면 `/상자관리 관리` 창의 「열쇠 다시 지정」으로 손에 든 뽑기권으로 바꾸면 됨).

## 1. 가구 뽑기권 `furniture_ticket`

**무엇을 넣었나**: 하우징 `housing-paper/src/main/resources/furniture.yml` 106개 중 97개.
- 뺀 것 ① 예전 임시 id 6개(`moon_rug`·`moon_banner`·`starry_wallpaper`·`cream_wallpaper`·`oak_floor`·`marble_floor`) — 저장된 방 배치를 지우지 않으려고 남겨 둔 옛 id 이고 그림이 없으며, 같은 이름의 새 가구(대리석 바닥·별밤 벽지·루미나 배너 등)가 따로 있다.
- 뺀 것 ② **미끼 상자 3종**(`bait_box_common`·`_rare`·`_unique`) — 지금 눌러도 "미끼 상자는 준비 중이에요"(미끼 생성 수치 미정, §32)이고 이름에 등급(일반·고급·유일)이 붙어 있어 "모두 같은 확률" 가구 상자에 섞기 어색함. 미끼 생성 기능을 정하면 그때 넣는다 (yml 에 `- furniture: bait_box_common` 줄 추가 또는 낚시도구 상자 쪽에).
- **넣은 것**: 꾸미기 가구 89종 + **특수 가구 8종**(기능이 있는 가구도 하우징에서 이미 동작하므로 "가구 전부"에 포함).

**확률**: 오너 결정대로 **모두 같은 확률** — 각 가중치 10 (가중치 합 970, 하나 1.03%). 가구는 등급이 없어서(오너 2026-10-20 "가구에는 등급을 넣지 않음") **전부 일반** 등급색.

**가구는 어떻게 주나 (새 보상 종류 `furniture:`)**
- 가구는 아이템이 아니라 권한(LuckPerms `chacademi.housing.furniture.<id>`, `/유저관리 <닉> 가구 주기` 와 같은 노드)이라, 뽑기 상자 보상에 **가구 보상 종류**를 새로 넣었다:
  ```yaml
  - furniture: sofa                                             # 가구 id (furniture.yml 의 키)
    icon: "magiccodex:textures/gui/housing/furniture/sofa.png"  # 결과 칸에 그릴 가구 그림 (furniture.yml 의 icon 과 같은 값)
    label: "2인 소파"                                            # 화면 이름 (가구 보상은 필수)
    amount: 1                                                   # 가구는 1 만
    grade: 일반
    weight: 10
  ```
- **지급 순서 (기존 영수증 규칙 그대로)**: ① 추첨 확정 + 개봉 기록(lootbox-receipts, 이번에 `furniture=` 줄 추가) 저장 → ② 같은 틱에 열쇠 차감 + 아이템 보상 넣기 + 영수증(PDC) + saveData → 연출 → ③ **가구 권한 주기** → 남은 아이템 우편 → ④ 기록 삭제.
- **멱등**: 권한은 여러 번 줘도 결과가 같다(이미 있으면 그대로). 그래서 서버가 ③ 중간에 꺼져도, 다음 시작·접속 때 영수증이 있으면 가구 권한을 **다시 준다**(복제 없음). 영수증이 없으면(②가 안 일어남) 기록을 버리고 열쇠도 그대로.
- 권한 주기가 실패하면(LuckPerms DB 문제 등) 기록을 지우지 않고 1분 뒤 다시(3번), 그래도 안 되면 다음 시작·접속 때 다시. 유저에게 "가구 지급이 늦어지고 있어요" 알림 1번. `/상자관리 대기` 에 "가구 N(재시도 n회)" 로 보임.
- 여는 순간 LuckPerms 가 없으면 열지 않음 ("지금은 가구를 받을 수 없어요", 열쇠 그대로).
- **화면**: 결과 칸에 가구 그림(PNG)을 그린다(하우징 보관함과 같은 그림). 표시용 아이템은 그림 아이템(PAINTING) + 이름(가구 이름) + 설명 "하우징 가구 · 내 방 꾸미기 보관함에 바로 들어가요" — 인벤토리에는 들어가지 않는다. 모드 없는 클라는 채팅 결과에 가구 이름.
- 하우징 보관함은 권한으로 보유를 판정하므로, 뽑은 즉시 내 방 꾸미기 보관함에 생긴다(다른 서버는 LuckPerms 동기화 뒤).

**이미 가진 가구가 나오면 — Claude 판단: 다시 뽑기 (오너 검수)**
- 이미 가진 가구(하우징과 같은 판정: 그 가구 권한이 있음)와 **이번 10개 열기에서 이미 나온 가구**는 추첨에서 뺀다. 즉 "아직 없는 가구 중에서 같은 확률로 다시 뽑기" (`LootBoxRules.drawUnique`).
- 이유: 가구 권한은 있다/없다만 있어서 중복은 아무 가치가 없다(꽝). 대체 보상은 무엇을 줄지 정해진 게 없다.
- 가구를 **전부 모으면** 열리지 않는다: "이 상자의 가구를 모두 모았어요 (열쇠는 그대로예요)". 남은 가구가 10개보다 적으면 10개 열기는 "받을 수 있는 가구가 N개 남아 10개 열기는 할 수 없어요. 1개씩 열어 주세요"(열쇠 그대로).
- 주의: **OP 계정**은 권한 판정상 모든 가구를 가진 것으로 보여(하우징 보관함도 전부 보임) 가구뽑기권이 "모두 모았어요"로 거절된다. 실제 확인은 OP 아닌 계정으로, 화면만 볼 때는 `/상자관리 테스트 가구뽑기권 10`(미리보기는 가진 가구를 빼지 않음).
- 관리 창에서 다른 아이템 보상을 섞어 넣어도 된다(그 보상은 가구를 다 모아도 계속 나옴).
