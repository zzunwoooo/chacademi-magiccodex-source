차카데미 정보창 UI 개발 프롬프트

첨부 approved-v4.png의 최종 디자인을 기준으로 정보창을 구현해 주세요. 본 전달물은 구현용 시각 자산·설계 패키지이며 라이브 서버 배포나 실제 기능 구현 완료를 의미하지 않습니다. 이 문서 전체를 개발 작업 지시로 사용하세요.

1. 최종 승인 범위
사용자 최종 수정은 “다 좋은데 주손 보조손만 빼줘”입니다. 기존 장착 장비 요약은 유지하되 주손·보조손 슬롯만 화면에서 제거합니다. 게임 데이터 자체를 제거하지 않습니다. 이전 칭호·장비 탭은 복원하지 말고 인라인 ‘칭호 자세히’, ‘장비 자세히’ 링크로 연결합니다. 본인·타인 모두 상단 제목은 ‘정보창’입니다. 무거운 장식, 거친 종이 질감, 과도한 노이즈를 추가하지 않습니다.

2. 3열 구성
왼쪽: 플레이어 초상/스킨, 이름, 접두·접미 칭호를 합친 단 하나의 칭호 행, 클래스 1~9, 기숙사. 클래스는 플레이어 도달 단계이지 등급·학년이 아니며 졸업 모자 아이콘을 쓰지 않습니다. 기숙사는 아르케온·루미나·베스티아즈·노크세르 값을 사용합니다.
왼쪽 하단: 인기도와 상승/하락 버튼, 하우징 좋아요 요약. 본인 버튼은 ‘내 방 가기’/‘친구 목록’, 타인은 ‘상대 방 가기’/‘친구 추가’. 하우징 좋아요와 방 방문은 서로 다른 동작입니다.
중앙 상단: 1:1 대전과 큐디치 카드 2개. 각각 실제 경지 PNG를 크게 배치하고 경지 이름, 레이팅, 랭킹을 표시합니다. 랭킹은 PvPProfile.rank > 0이면 표시, 그 외에는 ‘미집계’로 표시합니다. 두 모드의 값과 경지를 따로 바인딩합니다.
중앙 중단: 모험 기록. ‘발견한 마법’ 행의 발견(습득)/전체 마법 수, 진행 중 퀘스트 수, 추적 중 퀘스트의 이름·목표 current/required. 전체 마법 수를 240 또는 299로 고정하지 않습니다. 전역 모험 달성률은 정의되지 않았으므로 새로 만들지 않습니다. 진행 막대는 각 분모가 유효할 때만 계산하고 0~1로 제한합니다. 분모 0·미확인은 — 또는 빈 상태로 처리합니다.
중앙 하단: 장착 장비 9슬롯. 1행 머리·상의·하의·신발 4개. 2행 아티팩트·반지·귀걸이·목걸이·빗자루 5개. 주손/보조손 슬롯 없음. 슬롯 내부 아이템은 실제 장비 상태로 렌더링하며 예시 이미지를 고정 등록하지 않습니다.
오른쪽: 지능, 최대 체력, 현재/최대 마나, 마나 회복, 마법 가속, 방어력. 마법 가속 h의 재사용 대기시간 감소는 100*h/(100+h)%를 툴팁에 표시합니다. 레퍼런스 숫자 24 → 약 19.4%는 예시입니다. ‘상세 능력치’ 버튼은 넣지 않습니다.

3. 실제 데이터 및 연동 주의
기존 프로필 초상은 3D 스킨입니다. 본인 전용 PortraitClient의 1024x1536 PNG는 별도 UI 연결이 필요합니다. 타인 초상을 가져오는 경로는 확인되지 않았으므로 임의 접근·API를 만들었다고 가정하지 말고 기존 스킨 또는 중립 플레이스홀더를 사용하세요. 레퍼런스의 인물 그림은 예시이며 UI 정적 자산에 포함하지 않습니다.
칭호 접두·접미는 TitleProtocol 연동이 필요합니다. 임의 예시 칭호를 실제 보유 칭호나 기획 확정 문구로 취급하지 마세요. 긴 칭호는 단일 행 유지 + 말줄임 + 전체 내용 툴팁 처리합니다.
인기도는 nullable이며 실제 상승/하락 핸들러가 확인되지 않았습니다. 서버 저장·권한·중복 요청·쿨다운 검증이 필요한 연동 항목입니다. 미연결 버튼을 정상 동작처럼 연출하지 마세요. 미연결/불가 상태는 비활성 표시와 이유를 제공합니다.
하우징 좋아요는 요약 데이터 연결이 필요하며 클릭으로 방에 방문하면 안 됩니다. 기존 친구 요청 및 방 방문 기능은 해당 경로를 재사용합니다.
장비는 방어구·액세서리·Artifact·Motion 빗자루 상태를 모아서 읽어야 합니다. 미확인 값을 0으로 위조하지 말고 —로 표시합니다. 플레이어 비공개 필드는 기존 가시성·권한 규칙을 지킵니다.

4. 자산 적용
assets/tiers/*.png 9개와 tier-mapping.json은 실제 제공된 원본이며 재생성·재채색·덮어쓰기·파일 변환 금지입니다. 렌더링할 때만 종횡비를 유지해 contain 배치합니다. 이미지 안 투명 여백 때문에 가시 크기가 다를 수 있으므로 manifest의 visibleBounds와 layout-metrics를 참고하세요. 원본 픽셀 보존은 파일 해시로 검증합니다.
패널 6개, 능력치 아이콘 6개, 동작·프로필 아이콘 8개는 제작된 UI PNG입니다. 패널과 아이콘에는 텍스트를 굽지 않습니다. 글자, 수치, 닫기, 구분선, 진행 막대, 꺾쇠는 런타임 렌더링합니다. 슬롯은 동일 슬롯 패널을 9회 재사용합니다. 플레이어 초상·게임 아이템 아이콘·배경 월드는 동적이며 본 PNG 묶음에서 제외합니다.
조립 미리보기는 실제 제공 자산을 재배치한 검증용 예시입니다. 승인 레퍼런스와 완전한 픽셀 일치를 보증하는 화면 캡처가 아닙니다. 기준 배치와 코드 기반 자산 간 여백·모서리 차이는 visibleBounds 및 9-slice로 보정합니다. 새 기능을 구현 완료했다고 표기하지 않습니다.

5. 검수 조건
본인/타인 전환, 빈 칭호·긴 칭호, 클래스 1/9, 모든 기숙사, 미집계 랭킹, 서로 다른 두 경지, 마법 0/0 및 동적 전체 수, 추적 퀘스트 없음, 장비 빈 슬롯, nullable 값, 비공개 필드, 인기도 비활성, 높은 UI 배율을 검수합니다. 마지막으로 주손/보조손과 상세 능력치 버튼, 이전 칭호/장비 탭이 없는지 확인합니다. 모든 아이콘 투명도와 PNG 가장자리, 9슬롯 개수, 원본 경지 해시를 검사한 뒤 실제 연동 및 배포는 별도 승인 범위에서 진행하세요.

6. 인터랙션과 렌더링 규격
layout-metrics.json의 색상은 코드 렌더링용 값이며 PNG 픽셀의 단색 샘플을 뜻하지 않습니다. 제공 패널은 균일한 단색과 실제 알파로 만들었으며 거친 질감은 없습니다. 구분선 1px #35516D, 기본 진행 막대 높이 13px/반경 6.5px/트랙 #1C3554/채움 #80B7F8/외곽 1px #48617D. 닫기는 24x24 안의 두 대각선, 3px #F5D18A. 꺾쇠는 7x14, 1.5px #B6D9F4. 포커스는 2px #B6D9F4, 비활성 전체 알파 0.4입니다. 스케일링은 캔버스 전체에 균등 적용하며 글자와 선이 잘리지 않게 정렬하세요. 버튼의 클릭 영역은 시각 아이콘만이 아니라 버튼 사각형 전체로 잡으세요. 현재 지시의 픽셀 크기는 1672x941 기준입니다.
툴팁과 키보드 포커스/접근 가능한 라벨을 제공하며 숨긴 비공개 값이 툴팁에 새어 나오지 않아야 합니다. 버튼 hover/pressed/focus/disabled는 정상 상태와 구분하고 미구현 기능은 클릭 성공 피드백을 내지 않습니다. 제공 PNG에서 필요한 크기로 렌더링하되 원본 파일 자체를 재저장할 필요는 없습니다.

제작 방식: UI 패널/아이콘 20개는 깔끔한 코드 기반 SVG 도형으로 새로 제작하고 PNG로 렌더링했습니다. 생성형 이미지의 얼룩/노이즈를 지우는 후처리가 아닙니다. vector-sources에 확장 가능한 SVG 원본이 있으며, 실제 경지 9개는 제공 PNG 원본 그대로입니다.

마법 수 표시 범위: 승인 레퍼런스 라벨은 ‘발견한 마법’으로 유지합니다. 수치는 현재 설계의 습득/전체 집계와 연결하되 발견과 습득이 실제 데이터 모델에서 다른 의미라면 연동 전에 정의를 확인합니다. 별도 발견 카운터나 임의 합계를 발명하지 않습니다.
