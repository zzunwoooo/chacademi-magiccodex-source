첨부한 API 상자 레퍼런스와 PNG를 기준으로 기존 프로젝트에 개봉 연출 및 지급 처리를 구현해 주세요. 이 문서는 Claude에게 전달할 개발 요청이며, 이미지 제작 단계에서 코드/서버 패치는 수행하지 않았습니다.

1. 승인된 화면 및 연출
- reference/reference-corrected.png의 디자인을 그대로 따라 주세요. 기존 닫힌 상자와 열린 상자는 모두 동일 방향: 화면 왼쪽에 측면 손잡이, 오른쪽 앞면에 별 잠금장치가 보입니다. 개봉 시 좌우 반전시키지 마세요.
- 화면 중앙에 닫힌 상자 등장 → 작게 들썩임 → 뚜껑이 열리며 안쪽 빛이 새어 나오는 간단한 연출. 파괴/화염 연출은 추가하지 마세요.
- 일반 은백색, 고급 청록색, 유일 보라색, 전설 금색의 4종 내부광. PNG를 사용하고 승인되지 않은 배경/장식/색상으로 재설계하지 마세요.
- 1개 사용과 10개 사용을 모두 지원합니다. 결과는 1개일 때 중앙 단일 아이템, 10개일 때 5열×2행으로 표시합니다. 각 아이템의 실제 등급 색상을 적용합니다.
- 그림의 열쇠/물약/티켓/확성기는 시각적 예시일 뿐입니다. 실제 보상은 기존 서버 설정에서 읽고 확률, 비용, 보상 목록이나 새로운 규칙을 임의로 만들지 마세요. 10개 개봉의 대표 연출 등급 결정 정책은 기존 정책을 확인하고, 없다면 추측하여 추가하지 말고 확인 요청하세요.

2. 기존 아이템 오버레이 재사용
- 결과 아이템 위에 마우스를 올리면 현재 프로젝트에서 쓰는 기존 아이템 오버레이/툴팁이 표시되어야 합니다. 새 툴팁 디자인을 만들지 마세요.
- 서버에서 실제 지급 확정한 ItemStack 및 메타데이터를 그대로 사용하여 이름, 로어, 등급, 수량, 옵션 등 기존 툴팁이 제공하는 실제 속성을 보여 주세요. 결과용 임시 샘플/재추첨 ItemStack을 사용하지 마세요.

3. 모든 보상 자동 지급
- 확인 버튼을 눌러 수령하는 별도 단계로 만들지 말고, 서버에서 획득한 보상은 모두 자동 지급합니다. 결과 화면과 확인 버튼은 지급 결과를 보여 주고 닫는 용도이며 재지급 트리거가 아닙니다.
- 플레이어의 일반 인벤토리뿐 아니라 사용 가능한, 잠금 해제된 아공간 가방/인벤토리의 빈자리 및 기존 규칙상 병합 가능한 스택 공간도 함께 사용합니다.
- 잠겨 있는 아공간 페이지/슬롯은 절대 지급 대상 또는 잔여 용량에 포함하지 마세요. 잠금 해제 조건 및 권한은 서버의 실제 현재 상태로 검증하세요.
- 일반 인벤토리와 사용 가능한 아공간 공간을 포함해 넣을 수 있는 만큼 먼저 넣고, 그 후에도 남은 초과분만 기존 우편 시스템으로 보냅니다. 일부가 들어간 경우 전체 보상을 다시 우편으로 보내지 마세요.
- 일반 인벤토리와 아공간 사이의 배치 순서, 스택 병합 조건, 제한 슬롯 등은 기존 프로젝트 정책을 재사용하세요. 새로운 우선순위를 임의로 도입하지 마세요.

4. 기존 지급 경로도 함께 점검
- 이번 패치 때 기존의 '인벤토리가 꽉 차면 우편함으로 보내는' 모든 지급 경로를 검색하고, 이미 잠금 해제된 아공간 가방 용량을 포함하도록 패치되었는지 실제 코드와 테스트로 확인하세요.
- 빠진 경로는 동일한 공통 지급/잔여분 계산 처리로 수정하여 일관되게 동작하도록 해 주세요. 이번 상자만 고치고 기존 보상 지급 경로를 남겨 두면 안 됩니다.
- 변경한 경로와 이미 정상인 경로를 구분하여 파일/함수 단위 점검 목록 및 테스트 결과로 보고하세요. 검증하지 않은 경로를 완료했다고 쓰지 마세요.

5. 중복 지급/소모 및 복구
- 서버 권위로 1회 또는 10회 수량을 검증하고 사용 아이템의 소모, 확정된 보상, 실제 인벤토리/아공간 지급, 남은 우편 지급을 일관되게 처리하세요.
- 연속 클릭, 중복 요청, 재접속, 결과 창 재열기, 요청 재시도, 애니메이션 중 종료에도 같은 개봉 건이 다시 소모되거나 재추첨/중복 지급되지 않게 기존 트랜잭션/영속 기록/멱등 처리 구조를 사용하세요.
- 지급 중 저장 실패나 우편 실패 때 보상이 유실되지 않게 기존 복구 방식을 확인하고 실패를 감추지 마세요. 애니메이션 재생 완료 여부와 실제 지급 성공을 혼동하지 마세요.

6. 검증 항목
- 1개 및 10개 사용: 정확한 소비량, 확정 보상 수, 결과 항목 수, 실제 지급 수량 일치.
- 일반 인벤 여유, 일반 인벤 가득+아공간 여유, 아공간 일부 잠금, 전부 잠금, 양쪽 전부 가득, 일부만 수용 가능, 스택 일부 병합 후 잔여 우편.
- 잠긴 페이지는 단 한 슬롯도 쓰지 않는지 확인.
- 연타/재시도/재접속/결과 재열기/우편 실패 시 소모·지급 중복 및 유실 검증.
- 결과 툴팁이 실제 서버 보상 ItemStack과 일치하고, 10개 각각에 hover가 작동하는지 확인.
- 기존 인벤 가득→우편 지급 경로 전반에 같은 아공간 판정이 적용되는지 회귀 테스트.

자산 사용
- assets/의 PNG 5개는 1254×1254 RGBA입니다. 같은 캔버스와 바닥 기준점(약 x=698,y=1134)을 사용하세요. 원본 투명 여백을 자동 트리밍하지 마세요.
- 들썩임은 chest_closed.png의 작은 위치/회전 변화로 구현할 수 있습니다. 실제 프레임 애니메이션 파일이나 코드는 포함하지 않았습니다.
- AI 제작 이미지라 프레임 사이 세부 픽셀까지 완전히 일치하는 리깅 자산은 아닙니다. 방향/몸체 크기/기준점은 맞추었으며, 실제 엔진 합성에서 최종 확인하세요.
