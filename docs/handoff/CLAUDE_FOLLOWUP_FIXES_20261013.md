## 0. 먼저 읽을 것 (주의사항)

1. **빌드와 실게임 테스트는 하지 않았다.**
   - 사용자 PC의 Loom 캐시로 `javac --release 21` 타입 검사를 했다.
     - MagicCodex: yarn 1.21.4, 오류 0건. 기존 `CodexTextureFilterMixin`의 access widener 오류는 제외했다.
     - chacademy-motion 모드: Mojang 매핑 jar와 리맵한 Fabric API·playerAnimator를 사용했고, 오류 0건이다.
   - JUnit은 303개 중 295개가 통과했다. 실패 8개는 이 환경 문제다(netty-codec 없음, 한글 파일명 로케일, 테스트 리소스 경로).
   - 호스팅에서 Gradle 빌드와 테스트가 필요하다.
2. **비행 HUD(6번)는 사용자 검수를 기다리는 시안이다.** 사용자가 "디자인부터 만들어 보면 검수 후 승인"이라고 했다. 코드는 시안대로 넣었으니, 승인되지 않으면 `BroomHud.render`의 판 그리기 부분만 되돌린다. 기능 수정(위치 고정, 쿨타임 숫자 제거, 낙마 키 글씨)은 승인과 상관없이 필요하다.
3. **키세팅 UI(3-1번)는 사용자 지시에 따라 마우스가 없던 원래 디자인으로 되돌렸다.**
   - 배경은 `key_settings_base.png` 슬라이스이고, 아래 6칸도 원래대로 있다.
   - 여기에 마우스만 키보드 오른쪽에 추가했다. 키보드는 원래 아트를 84% 크기로 그린다.
   - 이후 Codex가 바꾼 동작은 그대로 유지했다: 물리 키나 엄지 버튼을 눌러도 편집창이 열리지 않고, Alt는 지정 불가다.
   - 아래 6칸은 HUD 순서(`orderedSlots`, 등록 순)를 보여준다. 우클릭하면 해제된다. 끌어서 순서를 바꾸는 기능은 없다(HUD가 등록 순서를 쓰기 때문).
4. **chat-layout 모드 호환:** `PlayerHudClient`의 HUD 레이어 람다는 이제 `screenNow()` 메서드로 화면을 읽는다.
   - `MagicHudChatMixin`(require=0)의 리다이렉트는 더 이상 걸리지 않는다. 채팅 중 HUD 표시는 MagicCodex가 직접 처리하므로 기능 차이는 없다.
   - 람다 개수와 순서는 그대로다.
5. **커스텀 인벤토리를 제거했다.** 사용자 선택은 "화면만 제거"였다.
   - 지운 것: 화면·레이아웃 클래스, 전용 mixin 7개, `textures/gui/inventory/*`, `followup/inventory_*`, `originals/inventory_atlas.png`, 관련 테스트.
   - 128px 아이템 아이콘과 반짝임은 유지했다.

## 2. 확인할 것

- 설정: 타이핑 중 Esc는 입력만 취소하고, 화면은 닫지 않는다.
- 채팅을 연 상태에서 좌측 상단 메뉴, 알림 카드, 스킬 HUD가 보이고 클릭되는지.
- 사거리 채움은 평면 홀로그램 방식(Codex 결정)이라 경사지에서는 지면과 어긋날 수 있다.
- 비행 HUD: 해상도별로 스킬바와 겹치지 않는지. GUI 배율이 클 때도 확인.
