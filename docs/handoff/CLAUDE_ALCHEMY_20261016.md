# 연금술 (경험치 제작 + 숨겨진 레시피) (Claude, 2026-10-16)

브랜치: `claude/alchemy-20261016`. 기준은 `claude/artifact-effects-20261015` @ `ac545d0`이고, 아티팩트 효과·소환까지 모두 포함합니다.

## 0. 먼저 읽을 것

- **Gradle 빌드는 못 했습니다.** 대신 아래를 확인했습니다.
  - 서버(`AlchemyBridge`, `ArtifactGrants`, `ItemsAdderItems`, `MailService`, 프로토콜): **Paper 1.21.4 API 실제 소스**(+Adventure·LuckPerms API 소스)로 javac 통과. SnakeYAML만 소스를 구할 수 없어 `YamlConfiguration` 껍데기로 대신했습니다(쓰는 메서드는 모두 실제 `MemorySection`/`FileConfiguration` 것).
  - 새 테스트 `AlchemyProtocolTest`(6개)·`AlchemyLayoutTest`(3개): 간이 실행기로 9개 통과.
  - Fabric 화면(`AlchemyScreen`, `AlchemyClient`): Minecraft 의존성이 없어 **실제 컴파일은 못 했고**, 기존 코드와 같은 시그니처의 껍데기로 타입 검사만 통과했습니다.
- **새 채널 `magiccodex:alchemy_request/response`.** 서버(MagicCodexBridge)와 모드를 같이 배포해야 합니다. 기존 채널은 바꾸지 않았습니다.
- **레시피는 아직 없습니다(오너: 아이템 목록은 나중).** `alchemy.yml`의 `recipes: {}`에 채우고 `/연금술관리 새로고침`.

## 1. 오너 요청

1. 경험치를 소모해서 제작하는 시스템. 레시피는 숨겨 두고, 알맞은 재료를 넣으면 발견됩니다.
2. UI는 연금 마법진 컨셉. GPT가 만든 PNG(`CHACADEMI_ALCHEMY_UI_PNG.zip`)를 사용합니다.
3. 위쪽 재료 칸을 누르면 **카테고리가 '재료'인 아이템만** 뜹니다(장비창 선택 창과 같은 방식).
4. 재료 순서는 상관없습니다. "재료 순서 무관" 글씨는 넣지 않습니다.
5. 글씨는 차카데미 전용 폰트(MagicCodex 폰트)를 씁니다. 레이아웃은 서로 겹치지 않게 합니다.
6. 거의 맞으면 "무언가 반응할 것 같다" 힌트를 줍니다.
7. 결과물은 인벤토리로, 자리가 없으면 우편함으로 갑니다.

## 3. 규칙 (서버가 결정)

- **재료(카테고리) 판정:** 아이템 설명(lore) **첫 줄**이 `settings.material-categories`(기본 `재료`)와 같으면 재료입니다. 괄호와 앞뒤 공백은 무시합니다(`[재료]`도 됨). 툴팁에서 아이템 종류로 보이는 바로 그 줄입니다. 예외로 넣을 아이템은 `settings.material-items`에 적습니다.
  - 재료로 쓰이는 칸은 인벤토리 0~35(핫바+가방)만 봅니다. 갑옷·보조손·장신구는 쓰지 않습니다.
- **아이템 키:** 아이템애더 아이디(`item:lily`)가 있으면 그것, 없으면 바닐라 아이디(`minecraft:sugar`)입니다. 같은 키면 이름·NBT가 달라도 같은 재료로 봅니다.
- **합성 버튼을 누르면:**
  1. 넣은 재료가 실제로 있는지 확인합니다. 없으면 거절하고 아무것도 쓰지 않습니다.
  2. 레시피와 정확히 같으면(재료 종류와 총 개수):
     - 경험치가 충분하면 재료와 경험치를 쓰고 결과를 줍니다. 처음 만든 레시피면 이때 **발견**합니다(LuckPerms `magiccodex.alchemy.recipe.<아이디>`).
     - 경험치가 부족하면 **아무 일도 일어나지 않습니다**(발견 없음, 차감 없음). 오너 결정 2026-10-16.
       - 발견한 레시피: 화면의 [합성] 버튼이 꺼지고, 눌러도 "경험치가 부족합니다. (필요 N)"만 띄웁니다. 서버도 같은 이유로 거절합니다.
       - 아직 발견하지 않은 레시피: 서버가 `no-exp-locked` 문구("경험치가 부족해 마법진이 반응하지 않는다.")로 거절합니다. 필요 경험치는 알려 주지 않습니다.
     - 예전 `discovered-no-exp` 문구와 "발견만 되는" 경로는 없앴습니다. 프로토콜 값 `DISCOVERED_NO_EXP`는 호환을 위해 남겨 두었지만 서버가 더 이상 보내지 않습니다.
  3. 아니면 아무것도 쓰지 않고 힌트만 줍니다.
     - **양만 다름:** 재료 종류는 같고 개수만 다르면 "재료는 맞는 것 같은데, 양이 조금 다른 것 같다…"를 띄웁니다.
     - **하나 차이:** 하나가 빠졌거나, 하나가 더 있거나, 하나가 바뀐 경우(레시피 재료 중 하나만 빼고 다 들어 있음) "무언가 반응할 것 같다…"를 띄웁니다.
     - **그 외:** "아무 반응이 없다."를 띄웁니다.
     - `settings.near-hint: false`면 힌트를 끕니다.
- **경험치:** 바닐라 경험치 **포인트**(레벨 아님)입니다. 서버와 클라가 같은 공식(`AlchemyRules`)을 써서, 화면의 "보유 경험치"와 서버 판정이 일치합니다. 차감 뒤 레벨·바를 다시 설정합니다.
- **결과물 지급:**
  - 결과 아이템을 먼저 만들어 봅니다. 결과 아이템이 없으면 재료를 쓰기 전에 거절합니다.
  - 인벤토리에 넣고, 남은 것은 `MailService.sendSystem`으로 우편 보냅니다(9개 묶음, 출처 키 `alchemy:<craftId>:<n>`).
  - 우편 기능이 없거나 저장에 실패하면 발밑에 떨어뜨리고 콘솔에 `ALCHEMY MAIL FAILED`를 남깁니다.
- **발견 판정은 `isPermissionSet`을 씁니다.** 그래서 op라도 자동으로 전부 발견된 것으로 보이지 않습니다. 테스트할 때는 `/연금술관리 발견 <플레이어> 전체`를 쓰세요.
- **숨김:** 발견하지 않은 레시피의 이름·재료는 클라로 보내지 않고, 잠긴 개수만 보냅니다.
- **요청 제한:** 합성 0.4초, 조회 0.2초입니다. 다른 보관함이 열려 있거나 커서에 아이템이 있으면 거절합니다(장비창과 같은 규칙).
- **로그:** `ALCHEMY CRAFT player=… recipe=… amount=… exp=… [new] [mailed=n] craft=<uuid>`, `ALCHEMY DISCOVER`, `ALCHEMY RESULT MISSING`.

## 4. 화면 (1672×941 기준, `AlchemyLayout`)

- **왼쪽:**
  - 마법진 그림은 고정입니다(그림의 빛줄기에 칸이 맞아야 해서 돌리지 않음).
  - 6칸은 그림의 빛줄기 끝(위·아래 55°, 좌우 수평, 반지름 228)에 있습니다. 가운데에 결과 고리가 있습니다.
  - 아래로 문구 줄(y708), "● 소모 경험치 N / 보유 경험치 M"(y748), [합성] 버튼(y812)이 있습니다.
  - 아직 발견하지 않은 조합이면 소모 경험치는 `???`, 결과 고리는 `?`입니다.
  - 발견한 레시피와 맞으면 결과 아이템이 흐리게 미리 보이고, 경험치가 표시됩니다.
- **칸 조작:**
  - 클릭: 재료 선택 창(서버가 보낸 '재료'만 표시, 남은 개수 표시, 다 쓴 것은 어둡게)
  - 휠: 수량 ±1(보유량까지)
  - 우클릭: 빼기
  - 칸 수는 `settings.slots`(1~8)입니다. 6이 아니면 원형으로 고르게 배치합니다.
- **오른쪽:**
  - "레시피" 제목, 검색창, "보유 재료로 제작 가능" 체크박스와 "발견 n / 전체", 6줄 목록(휠 스크롤, 스크롤바), 아래 안내 문구가 있습니다.
  - 잠긴 레시피는 자물쇠와 `???`로 보입니다. 검색 중이거나 필터를 켜면 잠긴 줄은 숨깁니다(이름 유출 방지).
  - 레시피를 누르면 그 재료가 칸에 채워집니다. 부족한 수량은 빨간 숫자로 보입니다.
  - 마우스를 올리면 재료·보유량·경험치 툴팁이 뜹니다.
- **연출(가산 합성, 시간 기반):**
  - 대기: 마법진이 은은하게 숨 쉬고, 칸이 찰수록 밝아집니다. 넣은 칸에서 중앙으로 빛줄기가 흐르고, 별이 돕니다.
  - 서버 응답 대기: 빛이 강해지고 별이 빨라집니다.
  - 근접 힌트: 마법진과 빛줄기가 깜빡입니다.
  - 아무 반응 없음: 잠깐 어두워집니다.
  - 제작: 섬광, 원형 파동, 결과 아이템이 튀어나옵니다.
  - 발견: 금빛 섬광, 금빛 고리 3겹, 별 파편이 퍼지고, 목록의 새 줄이 반짝입니다.
  - 사운드는 모두 바닐라입니다.
- **폰트:**
  - 제목·버튼: `title`(마루부리)
  - 이름·숫자: `hud_bold`
  - 라벨: `label`
  - 문구: `body`(프리텐다드)
- 겹침이 없는지는 `AlchemyLayoutTest`로 확인합니다. 실제 PNG와 폰트로 그린 소프트웨어 미리보기는 오너에게 전달했습니다.

## 6. 인게임 레시피 편집기 (10-17 추가, 서버만)

오너: "인게임에서 연금술 목록 편집할 수 있는 거, 아예 모르는 사람도 편하게. 일반 유저가 보는 게 아니니 UI는 대충."

- **서버 JAR만 바뀝니다.** 모드·프로토콜 변경 없음. 바닐라 상자 창을 씁니다.
- 새 파일 `AlchemyEditor.java`. `/연금술관리`(인자 없이) 또는 `/연금술관리 편집`으로 열립니다. 권한 `magiccodex.alchemy.admin`.
- **목록 창:**
  - `alchemy.yml`의 레시피를 모두 결과 아이템 모양으로 보여 줍니다. 꺼진 것도 "(꺼짐)"으로 표시합니다.
  - 버튼: 새 레시피, 사용법, 파일 다시 읽기, 쪽 넘기기.
- **편집 창:**
  - 재료 칸(`settings.slots`개)과 결과 칸: 아이템을 커서에 들고 클릭하거나, 내 인벤토리에서 쉬프트+클릭합니다. 아이템은 **복사만** 되고 빠지지 않습니다.
  - 빈손으로 칸 클릭: 좌클릭 +1, 우클릭 −1, 쉬프트+클릭은 비우기.
  - 이름표: 창을 닫고 채팅으로 이름을 받습니다. 그 채팅은 취소돼 다른 사람에게 보이지 않고(`AsyncChatEvent` + 예전 `AsyncPlayerChatEvent` 모두 LOWEST), '취소'라고 치면 그만둡니다.
  - 켜짐/꺼짐 토글, 경험치 ±1/10/100, 저장, 삭제(두 번 클릭), 목록으로.
- **저장 동작:**
  1. 검사: 결과 있음, 재료 1개 이상, 종류는 칸 수 이하, 서버에서 결과 아이템 생성 가능, 다른 레시피와 재료 조합이 같지 않음.
  2. 이름을 비워 두면 결과 아이템 이름을 씁니다.
  3. 새 레시피 아이디는 `recipe_<n>`으로 자동입니다.
  4. `alchemy.yml`에 기록하고(Bukkit YAML, 주석 유지) 바로 다시 불러와서, 열려 있는 연금술 창에도 반영합니다. 불러오기에 실패하면 **원래 파일로 되돌립니다**.
  5. 재료 카테고리가 아닌 아이템(lore 첫 줄이 '재료'가 아님)은 `settings.material-items`에 자동으로 추가해, 플레이어 재료 선택 창에도 뜨게 합니다(오너가 이전에 좋다고 한 규칙의 연장, 채팅으로 알려 줌).
- 아이템은 **키로만 저장**됩니다(아이템애더 아이디 / `minecraft:아이디`). 바닐라 아이템의 이름·NBT는 저장되지 않습니다.
- 로그: `ALCHEMY EDIT save|delete by=<관리자> recipe=<id>`.
